# 広告診断（らいすぴあ）

近藤米穀店「らいすぴあ」（愛知県西尾市、創業130余年。精米したての米を店頭・通販・ふるさと納税で販売）の集客を、**限られた予算で利益が出る形**に整えるためのスキル。扱う領域は3つ。

| 領域 | 入力 | 読むもの |
|---|---|---|
| A. Meta広告の成果診断 | 広告マネージャのCSV、または口頭の数値 | この SKILL.md |
| B. サイトのSEO / LLMO 点検 | リポジトリ、URL、HTML | `references/seo-llmo-checklist.md` |
| C. にしおさんぽGO の広告・宣伝 | 運営者の指示（「広告に追加」「画像を新しく」「アップ」） | `references/nishio-go-ads.md` |

どちらも「数値や実物を根拠に、具体的な操作まで落とす」ことが価値。推測で数字を作らない。

## A. Meta広告の成果診断

### 手順

1. **CSVがあるなら、まず集計スクリプトを回す。** 手計算は桁違いや列の取り違えが起きやすい。
   ```bash
   python3 scripts/diagnose_meta_ads.py report.csv --target-cpa 3000 --margin 35 [--level ad|adset|campaign] [--conv-col 購入] [--json out.json]
   ```
   - `--target-cpa`：1件の成果に許せる広告費（円）。無ければ全体平均CPAとの相対評価になる
   - `--margin`：粗利率（%）。売上（コンバージョン値）列があるときは損益分岐ROAS = 100 ÷ 粗利率 で判定する。価格の違う商品が混ざるとCPA比較では高単価商品が不当に悪く見えるので、売上があるなら ROAS を優先する
   - 日本語・英語どちらの列名にも対応。「時間別 → 日」の内訳があれば前半・後半の推移（CTR低下、CPA悪化）も出る
   - 出力は Markdown。そのまま提示してよいが、**必ず下の「提案」を足す**。表だけ返しても店は動けない
2. **CSVが無く数値だけなら**、同じ判定基準（下表）を頭の中で当てる。根拠の数値は必ず添える。
3. **目標CPAも粗利率も分からなければ聞く。** 客単価と粗利率が分かれば「損益分岐CPA = 客単価 × 粗利率」で目安を作れる。聞けない場合は「全体平均との相対評価」と明記する。
4. 判定を踏まえて**提案**を書く（下の出力形式）。

### 判定基準（スクリプトと同じ）

**判定**（CPAの場合。ROASは「CPAが安い」を「ROASが高い」に読み替え、増額は基準の1.3倍以上、停止は0.4倍未満、要改善は損益分岐未満〔粗利率が無い場合は全体平均の0.7倍未満〕）

| 判定 | 条件 |
|---|---|
| ⛔ 停止候補 | 成果0件で基準CPAの2倍以上を消化、または CPA が基準の2倍超 |
| ⏳ データ不足 | 成果0件で消化がまだ少ない、または成果3件未満で消化が基準の1.5倍未満。**早すぎる停止は機会損失** |
| 📈 増額候補 | 成果3件以上かつ CPA が基準より20%以上安い |
| 🛠 要改善 | CPA が基準より30%以上高い |
| ➖ 維持 | 上記以外 |

補正：増額候補でも「悪化サイン（bad）」が1つでもあれば維持に留める。維持でも bad が2つ以上なら要改善。

**気になる点（原因の切り分け）**

| サイン | 読み方 → 打ち手 |
|---|---|
| フリークエンシー 3.5以上（2.5で注意） | 同じ人に出しすぎ、飽き → 新クリエイティブ、オーディエンス拡大 |
| CTR 0.5%未満（中央値の0.6倍未満で注意、1.5%以上は良好） | 訴求・最初の1秒・画像・一言目 → クリエイティブ差し替え |
| CPM が中央値の1.5倍以上 | ターゲットが狭い、配置が割高、競合期 → 広め配信、Advantage+配置 |
| CTR は0.8%以上あるのにクリック後の成果率 1%未満（クリック50以上） | 広告は見られている → LP・価格・送料・購入導線を疑う |
| 後半CTRが前半より25%以上低下 | クリエイティブ疲れ |
| 後半CPAが前半より30%以上悪化 | 要注意。20%以上改善なら好転 |

表示1,000未満の項目は CTR / CPM の判断をしない（ぶれが大きい）。リーチは日別行を合算すると重複するので、複数行から出したフリークエンシーは「参考値」と断る。

### 停止判断の手順

「停止候補」は止めてよいという許可ではなく、**止める前に確かめる候補**。次の順に確かめ、止めるなら理由と浮いた予算の行き先を必ずセットで書く。

1. **データは足りているか**
   - 消化が基準CPAの2倍に届いていないなら止めない（データ不足）。CPAが基準の2倍超でも、成果が1〜2件しかないなら1件の増減で大きく振れるので、あと基準CPA1倍分ほど様子を見る
   - 期間の**直近2日は成果が後から増える**（Metaの既定の計測は「クリック後7日・表示後1日」）。直近2日を除いた期間でも停止候補か確かめる
2. **学習中ではないか**
   - 広告セットの作成直後や大きな編集の後（予算の大幅変更、ターゲット・入札・クリエイティブの変更）は、成果が約50件たまるか7日ほど経つまで成果が不安定。この間は「成果0件で基準CPAの3倍以上を消化」のような明らかな失敗でなければ止めない
3. **止めるより直すほうが早くないか**（気になる点で原因を切り分ける）
   - CTRが低い → クリエイティブの差し替え。広告セットは残して広告だけ入れ替える
   - CTRは良いのにクリック後の成果率が低い → 広告ではなくLP・価格・送料・在庫の問題。広告を止めても直らない
   - CPMだけが高い → ターゲットや配置を広げる。新米期（9〜11月）・年末はどの広告もCPMが上がるので、全体の中央値と比べる
   - フリークエンシーが高く後半CTRが落ちている → 飽き。新クリエイティブを追加し、古い広告から止める
4. **止める単位を選ぶ**
   - 同じ広告セットに成果の出ている広告があるなら、**悪い広告だけオフ**。広告セットごと止めると学習がリセットされる
   - 広告セット内のすべてが停止候補なら広告セットをオフ。キャンペーン単位で止めるのは訴求・商品そのものが合っていないときだけ
   - 削除ではなく**オフ**にする（成果の履歴と学習データを残し、季節が変われば再開できる）
5. **浮いた予算を動かす**
   - 増額候補があれば、そこへ1回20%以内ずつ数日おきに移す
   - 無ければ新しいクリエイティブのテストに回す。全体の予算を減らすのは、全体が赤字（全体ROASが損益分岐未満、または全体CPAが基準超）のときだけ

停止の提案は「今すぐ止める（明らかな赤字・データ十分）」と「○日後に再判定（学習中・データ不足気味）」に分け、再判定の条件（例：あと¥○○消化しても成果0件ならオフ）を数字で書く。

### 提案を書くときの前提

- **Metaの学習を壊さない**：予算変更は1回20%以内を数日おきに。学習期間中の頻繁な編集は避ける。週50件の成果に届かない広告セットは統合して予算を集中。Advantage+配置・広めのターゲットは有力な選択肢
- **停止で浮いた予算の行き先を必ず書く**（増額候補へ、または新クリエイティブのテストへ）
- **米屋の季節性**：新米 9〜11月、年末年始の贈答、ふるさと納税の駆け込み 10〜12月、梅雨〜夏の保存・虫対策需要。提案の時期に合わせる
- **店の実際の強み**を使う：精米したて、5代目の目利き、精米品質AI判定での検品、愛知県産・西尾の品種、オリジナルブレンド（おにぎりがうまい米、花子、コスパ米）
- 成果件数が少ない項目は結論を急がない。「データ不足」は正当な判定

### クリエイティブ案の法令ルール

- **景品表示法**：「日本一」「最高級」「どこよりも安い」など根拠のない最上級・比較表現を使わない
- **食品表示**：産地・品種・年産・精米日は事実の範囲で。「1等米」は農産物検査で格付けされた場合のみ
- **薬機法・健康増進法**：健康効果を断定しない（「〜に効く」「ダイエットに」は不可）
- primary_text は125字前後、headline は25字以内。1案に訴求軸は1つ

### 出力形式（Markdown）

```
# Meta広告 診断（期間）
健康状態: 良好 / 注意 / 要対策
## 要約（3文以内）
## 主な発見（重要度順に3〜5個。各項目に根拠の数値と影響）
## やること（優先度順に3〜7個。「今すぐ／今週中／今月中」、対象（キャンペーン/広告セット/広告名）、操作、理由、期待効果）
## 予算配分の見直し（金額または割合で）
## 次の広告案（2〜3個。訴求軸・本文・見出し・ビジュアル）
## 検証したいこと（A/Bテスト1〜3個。仮説・方法・見る指標）
## 判断の前提・データの限界
（続けて、スクリプトの判定表）
```

## B. サイトのSEO / LLMO 点検

店のサイト（精米品質AI判定 ricepia-judge.vercel.app、翔米ECなど）について「検索に出したい」「AIに引用されたい」「サイトを見直したい」と言われたら、`references/seo-llmo-checklist.md` を読んで点検する。ファイルに点検項目・優先度・実装の型（JSON-LD、llms.txt、解説ページ）と、**捏造してはいけない情報**（住所・電話・SNS・氏名などの店の実体情報）の扱いが書いてある。

点検結果は「できていること／優先度順の改善案／ユーザーに確認が必要なこと」の3部構成で返し、実装を頼まれたら小さなコミットに分けて進める。

## C. にしおさんぽGO の広告・宣伝

お店のお散歩ゲーム「にしおさんぽGO」（go.ricepia.jp）を広告に出す・宣伝の材料を作り直す・ricepia.jp のお知らせ欄を上げる、と言われたら `references/nishio-go-ads.md` を読む。Google広告のスクリプト（`tools/google-ads-*.js`）、広告の画像・動画（Actions「Make Nishio promo」）、タイトルロゴとアイコン、ricepia.jp へのアップロードの手順がある。

- この環境からは Google広告・Meta・LINE・インスタの管理画面に入れない。貼って動かすスクリプトか、アップロードする画像（どこにどれかの表つき）を用意して渡す
- お金がかかり始める操作（キャンペーンを「有効」にするなど）は、運営者が管理画面でする。そのことをはっきり書く
- 広告の文は A の「クリエイティブ案の法令ルール」に従う（「無料・登録なし」など、本当のことだけ）
