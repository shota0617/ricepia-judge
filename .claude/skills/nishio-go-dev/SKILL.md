# にしおさんぽGO の 開発の 進め方

運営者（ユーザー）の 指示を まとめた もの。コードで できる ところは `scripts/` に ある。
広告・宣伝の 材料（Google広告・広告の 画像・ロゴ・ricepia.jp の アップロード）は 広告診断スキル（`.claude/skills/kokoku-shindan/` の C、`references/nishio-go-ads.md`）。

## いつも 守る こと

- **返事は 日本語**。GitHub の コメントも 日本語。
- **マージ・公開は、ユーザーが「マージ」か「マージ公開」と 言った ときだけ**。Codex の 指摘が なくても、CI が 緑でも、自分からは マージしない。
- 作業は セッションで 決められた 作業ブランチ（例 `claude/…`）で。main には 直接 push しない。
- **1つの 改善ごとに**：作る → プレイテスト → コミット → push → PR → 「@codex review」→ 指摘を 直す（スレッドに 返事・解決・もう一度「@codex review」）。
- コミット・PR・コード・コメントに **モデル名を 書かない**（`scripts/precommit.sh` が 見はる）。
- `tools/blender/__pycache__` は コミットしない。スクショや プレイテストの 出力は **リポジトリの 外**（スクラッチの フォルダ）に 置く。リポジトリの 中で スクショの 台本を 動かすと png が 入りこむので、台本は スクラッチの フォルダで 動かす。
- コミットの おわりと PR の 本文の おわりには、そのセッションの システムが 示す クレジット行（Co-Authored-By・Claude-Session、PR は 🤖 Generated with … と セッションの URL）を 付ける。
- GitHub に 書く コメントの おわりには 次を 付ける：

  ```
  ---
  _Generated by [Claude Code](https://claude.ai/code)_
  ```

## ループで みがく テーマ

「ループ」「朝まで ループ」と 言われたら、1回に 1つ、次の テーマから えらんで みがく（`docs/play-weekly.md` の 直す 候補が あれば そちらが 先）。

- **大きい 文字・シンプル**：小さい 字・うすい 字・数の ない 札を へらす（運営者の声「大きい文字シンプルに」）。
- **クセに なる 転がり方**：さわって 気持ちいい 手ごたえ・音・ベストを 追いかける 楽しさ。
- **西尾らしさ**：三河弁・西尾の 名物（抹茶・うなぎ・西尾城・お米・てんてこ祭 など）・西尾の 景色。事実には 出典、言いすぎない。
- **バイラル ループ**：遊ぶ → 見せたく なる → 見た 人が すぐ 遊べる。
- **西尾の 素朴な かわいさを 随所に 散りばめる**（運営者の声 2026-10-28）：大きな しかけ より、遊んで いて ふと 気づく 小さな かわいさを あちこちに。
  - 例：田んぼの すずめ・あぜの カエル・茶畑の 茶つみかご・干潟の カニ・ねこ・お米の ちょっとした 表情や しぐさ・三河弁の やさしい ひとこと（「〜じゃん」「〜だら」「〜りん」）・西尾の 季節の 小さな もの。
  - ドット絵の 手ざわり（四角で 描く・色は 少なく）で、ほのぼの。キラキラ・派手より、のどかで あたたかい 感じ。
  - 画面を ちらかさない（シンプルが 先）。出すのは たまに・小さく。遊びの じゃまを しない（お米の 道を ふさがない・窓に かぶせない）。
  - ポイントは つけない（見つけて うれしい だけ）。西尾に いる もの・ある ものだけ（事実に 出典、言いすぎない）。ほかの ゲームの 絵・名前・音は 使わない。

## 1つの 改善の 流れ

0. **何を 直すか えらぶ（ループの とき）**：`docs/play-weekly.md`（遊んだ 人の ★と ひとことの 週の まとめ。毎週 月曜に 自動で 書きかわる）の「直す 候補」が あれば、それを 先に。無ければ 上の「ループで みがく テーマ」から。
1. **調べる**：関わる コードを 読む（めいろ＝`nishio-go/pixel.js` の `mz…`、転がり＝`rollStep`・`riceFeel`、ゲームの 状態＝`nishio-go/game.js`）。「研究」と 言われたら、なぜ そうするかを 先に 考えて docs に 書く。
2. **作る**：まわりの コードに 合わせる（下の「コードの 書き方」）。
3. **見て 確かめる**：Playwright で スクショを 撮って 自分の 目で 見る（窓・町名の 帯・ごほうびの 窓が かぶって いないか。かぶったら 閉じてから 撮る）。数字（速さ・回数・時間）も はかる。
4. **プレイテストに チェックを 足す**：`tools/playtest.js` に `R.checks.<名前> = …` と、下の 合格条件に `need(c.<名前> && c.<名前>.ok, '…')`。テスト用の API は `window.nishioPixel`（例 `maze.padsNear`・`rollPut`）に 足す。
5. **docs に 書く**：めいろ＝`docs/meiro.md`、転がり方＝`docs/korokoro.md`、滞在・また来る＝`docs/retention.md`。「運営者の声「…」（日づけ）」で はじめる。
6. **プレイテスト**：`scripts/playtest.sh <足した チェック名>`（8分くらい。`ok: true`・failures 0・errors 0 に なるまで 直す）。
7. **コミット**：`git add <ファイル>` → `scripts/precommit.sh` → `git commit`（題は「にしおさんぽGO：〜」、本文は 何を・なぜ）。
8. **push**：`git push -u origin <作業ブランチ>`（ネットの エラーなら 2・4・8・16秒 あけて 4回まで）。
9. **PR**：GitHub の MCP（`create_pull_request`。ツールが 見えなければ ToolSearch で 読みこむ）。本文は `pr-template.md` の 形。続けて `add_issue_comment` で 「@codex review」、`subscribe_pr_activity` で 見はる。
10. **ユーザーへの 報告**：何を 作ったか・どう 確かめたかを 日本語で 短く。スクショが あれば 送る。最後に「マージは『マージ』と 言っていただいてから」。

## Codex の 指摘が 来たら

- 指摘は 鵜呑みに しない：ほんとうに 起きる 道すじを たどる。起きるなら 直す。
- 直したら プレイテスト → コミット（本文に「Codex の 指摘：…」）→ それぞれの スレッドに 返事（「ご指摘のとおりでした。<sha> で 直しました。…」）→ push → スレッドを 解決（`resolve_review_thread`）→ もう一度 「@codex review」。
- 直さない ときは、理由を スレッドに 書き、ユーザーにも 伝える。

## 「マージ」と 言われたら

1. `merge_pull_request`（squash、`expectedHeadSha` に PR の いまの 先頭）。
2. 見回りの 予約（send_later）を 消し、`unsubscribe_pr_activity`。
3. `scripts/after-merge.sh` — 作業ブランチを 新しい main に そろえて push（force-with-lease）し、main の Vercel デプロイを 待つ。
4. 「公開まで 終わった」か「Vercel が 失敗（例：Account is blocked）」かを 報告する。Vercel の アカウントの 問題は コードでは 直せないので、ダッシュボードの 確認を お願いする。

## PR の CI が 赤い とき

- `scripts/deploy-status.sh <sha>` で Vercel の 状態を 見る。main（前回 マージ）では 緑だったのに このPRで 赤い → コードの せい。直して push。
- 「Account is blocked」など、どの コミットでも 同じ 失敗 → このPRの せいでは ない。PR に 1回だけ コメント（何が 失敗・なぜ このPRの せいでは ないか・直すには 何が いるか）して、ユーザーに 伝える。

## コードの 書き方（にしおさんぽGO）

- コメント・docs・画面の 文字は、やさしい 日本語で 言葉の 間に 空白（「お米の 右よこに「×12」」）。まわりの 書き方に 合わせる。
- 新しい しかけには、なぜ そうしたか（運営者の声・ねらい）を コメントの 1行目に。
- 描く ものは **四角（fillRect）で**。Godot の 記録係（`rec`）には ellipse が なく arc は 何も しない。
- 描くのは **画面の 中だけ**（`tx0..tx1`・`ty0..ty1` で しぼる）。まわりの 区域の ぶんまで まいコマ 描くと 重くなり、テストが 落ちる。区域は `mzArea`（読みに いく）と `mzAreas.get`（読めた ぶんだけ）を 使いわける。
- `localStorage` は いつも try/catch。キーは `nsg_…`。日づけは 日本の 日（`jstDay()`・game.js の `ymd()`）。ひらいた まま 日づけを こえる ことも 考える。
- 同じ 所で ふやせる もの（コンボ・ひろう もの）には **ポイントを つけない**（ぐるぐる まわって かせげない ように）。数・音・ベストで 楽しませる。
- めいろを **通れなく しない**（逆から 来たら 何も しない など）。
- 窓が 出ている 間（`mapCovered(true)`・`sightBusy()`）は 動きと 時計を 止める。
- 効果音は `sfxCtx()` から。音が 出ない 端末の ために try/catch。

## プレイテストの こつ

- テストの 画面は 遅い ことが ある。「1.5秒で 〜」の ような 決めうちの 待ちは しない。〜に なるまで（上限つきで）待つ。
- お米を 動かす テストは、本の できごと（`.medashi`）・ごほうびの 窓（`#reward`）・町名の 帯（`nishioPixel.here.banner`）が 出て 止まる ことが ある。置く 前に 閉じる。
- 落ちたら、まず main でも 落ちるか 確かめる（`git stash` で もどして 同じ テスト）。main でも 落ちるなら テストの 待ち方の 問題。
