# トラクターのゲーム（tractor.html）

田んぼをトラクターで耕すブラウザのゲーム。公開先は go.ricepia.jp/tractor.html（Vercel が `main` を公開する）。

- `tractor.html` 1 ファイルに全部入っている：three.js r128、CDN から読む。
- 車体と田んぼの 3D は `tools/tractor/`（Blender で作った glb。`build_tractor.py`・`build_field.py`）。
- 季節：`?season=haru|aki|shirokaki`（春の田起こし 4 月／秋起こし 10 月下旬／代かき 5 月）
- 時間：`&time=asa|hiru|yu|yoru`
- 天気：`&w=hare|kumori|ame`
- そのほか：`&art=`（田んぼアート）・`&easy=0|1`（かんたんアシスト）

## ぜったいに守ること

- **車体にメーカーのロゴ・文字を入れない。**
- **glb は 10MB 以下。** 大きな作りなおしは避ける。
- **マージと公開は自動。** 条件（下の 7）がそろったら、たずねずにマージする。
- **Vercel が失敗したらマージしない。** 何が起きているか報告する。
  - 「Account is blocked」はアカウント側の問題。PR に 1 回だけ書いて、ユーザーに確認をたのむ。
- **「マージなし」と言われた間は、マージしない**（例：「朝までマージなしで」）。
- **モデル名（モデルの識別子）を**、コミット・PR・コード・コメントに**書かない**。
- **トークンや API キーを、チャットに貼ってもらわない。**
- **書いた変更は、ターンを終える前に必ずコミットして push する**（Stop フックが止める）。
- コミットメッセージの終わりには、そのセッションで指定された 2 行（`Co-Authored-By:` と `Claude-Session:`）を付ける。
- PR 本文の終わりには、「🤖 Generated with [Claude Code](https://claude.com/claude-code)」とセッションのリンクを付ける。
- GitHub のコメントの終わりには、次を付ける：

  ```
  ---
  _Generated by [Claude Code](https://claude.ai/code)_
  ```

## 1 回分の進め方（リアリティ磨きのループ）

1. **調べる**：改善点を 1〜2 個えらぶ。あわせて、SNS から農家の声をさがして足す（下の「SNS から農家の声をとりいれる」）。調べる先は 3 つ。
   - **農家の発信**：X の投稿。`grok-research.yml` を `topic: tractor` で回し、ジョブのログを読む。
     - xAI のクレジットが切れると 403 になる。そのときは WebSearch に切りかえる。
   - **メーカー資料**：クボタ・ヤンマー・三菱マヒンドラの取扱説明書や点検の案内。
   - **公的資料**：農林水産省・県・市・普及センター・図鑑（Canon 野鳥写真図鑑・サントリー日本の鳥百科・Honda 生きもの図鑑など）。
   - 出典がはっきりしないもの（例：西尾市の夕方のチャイムの曲）は、作らない。
2. **作る**：
   - コードのコメントに「何が本物か」と出典を書く（このファイルの書き方にそろえる：やさしい日本語・短く）。
   - 遊ぶ人が知っておくとよいことは、操作の表「本物の耕し方」にも書く（`<a href>` で出典）。
3. **テスト**（下の「テスト」）：
   - 春・秋は PC で、代かきはスマホ（390×844）で、通しで運転する。
   - 変えた所の確認スクリプトと、スクリーンショットを見る。
4. **コミットして push**：ブランチは `tractor-blender`。PR がなければ作る。
5. **Codex にレビューしてもらう**：PR に `@codex review` とコメントする。
   - 何を変えたか（コミットと関数名）を書き、「strictly」と頼む。
   - リアリティを見てほしいときは、「農家やメーカーが見ておかしい所・季節・時間帯・数値・生きもの・安全でない助言を、行と出典つきで」と頼む。
6. **指摘を直す**：
   - 指摘は出典で確かめてから直す。
   - 各スレッドに「どのコミットで何を直し、どう確かめたか」を返信して、resolve する。
   - 指摘がなくなるまでくり返す。
7. **マージと公開（自動で行う。ユーザーにたずねない）**：
   - マージしてよい条件は 4 つ。ぜんぶそろったら、その場でスカッシュでマージする。
     - PR の最新のコミットで、Vercel のチェック（プレビュー）が成功している。
     - 最新のコミットへの Codex レビューが「指摘なし」で、未解決のスレッドがない。
     - 通しのテストが通っている。
     - 「マージなし」と言われた間ではない。
   - 1 つでも欠けたらマージしない。何が足りないかを報告する。
     - Vercel の「Account is blocked」はアカウント側の問題。ユーザーに確認をたのむ。
   - マージは GitHub の MCP の `merge_pull_request`（`merge_method: squash`）で行う。
     - タイトルは PR のタイトル。本文は入れたものの要点と、指定された 2 行。
   - **公開の確認**：マージしたあと、`main` のマージコミットの Vercel のステータス（本番のデプロイ）が成功になるのを待って、確かめる。
     - このコンテナからは go.ricepia.jp に届かない（403）ので、GitHub のステータスで確かめる。
     - 失敗したら、ログを読んで原因を報告する。コードの問題なら、直して新しい PR を出す。
   - **マージのあとも作業を続けるとき**：マージした PR は使わない。
     - `tractor-blender` を最新の `main` から作りなおし、新しい PR にする。
     - 例：`git fetch origin main && git checkout -B tractor-blender origin/main`、`git push --force-with-lease`。
     - マージ済みのコミットだけのときに限る。マージされていないコミットが残っていれば、`main` の上に載せなおす。
   - **ユーザーが「マージ公開」「マージ」と言ったとき**：
     - 条件を待たずに、その場でマージと公開まで行う。Codex のレビューがまだ終わっていなくてもよい。報告で「Codex は終わる前にマージした」と書く。
     - ただし Vercel のプレビューが失敗しているときは、マージしても公開されない。理由を短く伝えて、マージするか待つかをたずねる。
     - ユーザーが Vercel を直したら、PR の最新のコミットで Vercel をもう一度動かす。空のコミットは使わない。
       - `main` が進んでいれば、`main` を PR のブランチにマージして push する（本物の変更なのでデプロイが動く）。
       - `main` が進んでいなければ、ユーザーに Vercel の画面で「Redeploy」してもらう。
     - リポジトリの `steward` スキルは「マージは言われたときだけ」。トラクターの PR は、このスキルの自動マージを優先する（ユーザーの指示）。
   - **手順の細かいところ**：
     - Vercel の状態：`.claude/skills/nishio-go-dev/scripts/deploy-status.sh <sha> --wait`（GitHub のステータスを読む。成功で終了コード 0）。
     - `merge_pull_request` の `expectedHeadSha` は 40 文字のフルの SHA（`git rev-parse HEAD`）。
     - Codex が 1 時間以上「Running」のままなら、止まっている。`@codex review` をもう一度コメントする。
     - マージしたら、その PR の見はり（`subscribe_pr_activity`）を止める（`unsubscribe_pr_activity`）。
     - 次の作業は `tractor-blender` を `main` から作りなおし、新しい PR を作って見はる。
8. **報告**：日本語で短く。
   - 入れたもの・PR のリンク・Codex の結果。
   - Vercel の状態と、マージ・公開したか（しなかったなら、その理由）。

**時間を区切ったループ**（例：朝 8:00 まで）のとき：
- 最後の 1 時間前に、全部のテスト（下）をもう一度流す。
- PR の本文を、入れたもの・出典・テストの結果に書きなおす。

## SNS から農家の声をとりいれる

ゲームの「農家の声」（`VOICES`）は、本物の農家さん・研修生の言葉を要約したもの。その場面になったら 1 回だけ出す（`voice('key')`）。1 回分のループのたびに、SNS から新しい声をさがして足す。

**くわしい拾い方・控え方・ゲームの動きへの作りかえ方は、`tractor-sns` スキル（`.claude/skills/tractor-sns/SKILL.md`）にまとめた。** 「農家の声を拾う」「このスキルをループ」と言われたら、そちらを回す。

1. **集める**：
   - **X**：`grok-research.yml`（`topic: tractor`。focus に「米農家さんの本人の言葉を短く、投稿の URL つき」）を回し、ジョブのログ（`research.json`）を読む。
     - xAI のクレジットが切れていると 403 で失敗する。そのときは下へ。
   - **ほかの SNS・発信**：WebSearch で、次の場で農家さん本人が書いた・話したものをさがす。
     - note・ブログ・Instagram・YouTube・Facebook
     - 新規就農者・JA・普及センターの研修の報告
   - 1 件ごとに、だれが（アカウント名か、どんな人か）・どこで（URL）・いつ を控える。
     - 本人の発信で、出どころがわかるものだけ使う。うわさ・まとめ記事の孫引きは使わない。
2. **えらぶ**：ゲームの場面に結びつく声だけにする。
   - 場面の例：まっすぐ・旋回・四隅・ぬかるみ・エンスト・藁・ひこばえ・タニシ・カラスやサギ・代かきの水・雨のあと・朝や夜・安全。
   - 安全でない話（回っている爪に手を出す など）は、そのまま出さない。正しい手順の案内といっしょにするか、使わない。
3. **書く**：
   - `VOICES` に `key: ['要約（やさしい日本語・1〜2 文）', '出どころ（@アカウント（X の米農家さん）・note「…」・○○県の研修 など）']` を足す。
   - 本人の言葉をそのまま長く写さない。短く要約する。
   - **もとの話のリンクを、はじめの画面の「農家の声」（`<details class="how">` の 1 行）にも必ず足す**。
     - 書く内容：要約・`<a href="URL">` だれの・どこの話か。
     - 終わりの画面は「はじめの画面の『農家の声』に、もとの話がある」と書いているので、リンクがないと うそになる（Codex に指摘された）。
   - 出す場面に `voice('key')` を置く。
     - 1 回だけ出る。知らせ（toast）が出ているあいだは待って順に出る。
     - 似た声が続かないように、場面ごとに 1 つ。
   - コミットとコードのコメントに、集めた時期と方法（例：「X の米農家さんの投稿（2026 年 10 月。Grok の x_search）」）を書く。
4. **確かめる**：
   - その場面を `game.sim` で作り、声が出ること（`game.heard` に入る・toast の文）を確かめる。
   - 通しのテストで、声が多すぎて ほかの知らせ（コーチの手順など）をじゃましないこと。

## これまでにユーザーが頼んだこと（方向性）

- 田んぼアート（デフォルトのお題あり）。
  - お題は やさしい順にならべる（★ がむずかしさ）。はじめは いちばんやさしい「四角」。上手に描けたら、終わりの画面から 次のお題へ（「最初からハート型に耕すのは難しいので簡単なものから」）。
- 点数：その場で出す点数（リアルタイム）と、腕前で決まる点数。
- 農家の声：X の米農家さんの投稿から、場面に合わせて出す（Grok で集めた声も）。
- 操作をわかりやすく。初心者向けの手助け（🔰 かんたんアシスト：畦の手前で止まる・速さの上限・点数は 8 割）。
- リアルなエンジン音：ディーゼルの回転・負荷・冷えたときのカラカラ・キャビンの中と外。
- リアリティ磨き：
  - 機械：倍速ターン・PTO 1/2 速・予熱・DPF・水温計・レバー。
  - 天気：晴れ・くもり・小雨、夜。
  - 季節の田んぼ：わだち・ひこばえの巻きつき・ジャンボタニシ・給水栓・水もれ。
  - 畦と道ばたの草花。
  - 季節と時間帯に合った鳥と虫。
- Codex のレビューは厳しめに。コードだけでなく、リアリティもレビューさせて直す。
- マージと公開も、このスキルで自動で行う（条件がそろえば たずねない）。「マージ公開」と言われたら、その場でマージして公開まで確かめる。
- 畦の農家さん（田んぼの持ち主）が運転を見ていて ダメ出しする（ふきだし・西尾の三河弁。「農家さんがダメ出ししてくる」）。点数のつけ方と同じ所を言う。
- SNS から農家の声をとりいれる（X・note・ブログ・Instagram・YouTube など。毎回のループで）。

## テスト（ヘッドレス Chromium）

Chromium と Playwright は入っている（`require('playwright')`）。three r128 は `scripts/` に入れる：

```sh
cd .claude/skills/tractor/scripts && npm i --no-save --ignore-scripts three@0.128.0   # node_modules は git に入れない。入れられないときは npm pack three@0.128.0 --ignore-scripts で取りだして node_modules/three に置く
node tooshi.js haru t pc "&easy=0"            # 春・PC の通し
node tooshi.js aki t pc "&easy=0&time=yu"     # 秋の夕方
node tooshi.js shirokaki t mobile ""          # 代かき・スマホ（かんたんアシストあり）
node combo.js                                 # 季節 3 × 時間 4 × 天気 3 の 36 通りを開いて少し走る
node firstmin.js                              # 最初の1分：知らせの文の かっこ・のんびりの大きな数字（スマホ縦で 1 回なぞる）
```

- **最初の1分の確かめ**（`firstmin.js`。サイクル259）：
  - 知らせの文（吹き出し・短い文）で かっこが合わなくならないこと。
  - スマホ縦で 1 回なぞって耕したら、のんびりの大きな数字が 0% のままでないこと（田んぼアートは地図の「でき」と同じ数、お題なしは小数 1 けた）。
  - なぞりは CDP の本物のタッチで入れ、時計をにせものにして ページの `frame()` を 0.05 秒ずつ手で回す（`game.sim` は `frame()` を通らないので、計器や最初の1分の時計が進まない）。
  - エンジンの始動（セル）は本物の時計で進む。にせものの時計にする前後で 2〜3 秒待つ。
  - 待ったあとは にせものの時計を本物の時計に合わせなおす（待つ間に 予約ずみの 1 こまが回ると、時間が逆もどりして ヒントの計算がこわれる）。
  - サイクル260 で足したもの：ヒントどおり前へ なぞるだけの人が畦の手前で止まったら「横へ なぞる」見本が出ること、見本どおり 3 回で向きが 45° 以上変わること、自動で下ろす知らせ「…を下げました」が 1 回だけのこと。ぜんぶで 2 分ほど。
- **なぞりと畦**（サイクル260 でわかったこと）：
  - 運転席から なぞれるのは鼻先より先の地面だけ。畦の 1m 手前で止まると、どの なぞりも最初の点が「まっすぐ前」になる。止められている間（`TRACE.blockT`）は、指のある側へ切って抜ける。
  - なぞりの点は畦から 1.5m 内側まで（`TRACE.clampIn`。幅のせまい作業機は いちばん外の列のまん中＝0.5m + 幅の半分 まで。`clampM`）。畦の線の上まで許すと、畦と平行に 作業機のはしが 4cm まで寄って動けなくなる。
  - なぞりでは後ろへ下がれない。確かめるときは、畦で止まったあとに 横へなぞって動けるかを見る。
- **曲がり方**（サイクル262。運営者の実機の声 2026-11-10「曲がり方がわからない」）：
  - 曲がるには 横へ なぞる。遠くの地面（ボンネットより上の帯）を横へ なぞった線は、3.5m 先まで手前へ寄せて すぐ曲がる（`TRACE.pull`。画面の上で 横の動きが たての 1.5 倍より大きいとき）。寄せないと「9m まっすぐ行ってから横」になり、向きが変わらない。
  - 見きわめは画面の上で（地面の上で見ると、走りだしの視点のゆれで 遠くの点が前後に 1m 以上動く）。
  - 「横へ なぞる」見本（`HINT.turn`）が出るとき：畦で止められたとき／前に耕す所がないまま 2.5 秒止まったとき／まだ一度も曲がったことのない人が 4 秒止まったとき。耕す所が まっすぐ前に来る・40° 曲がれる まで出したまま。
  - 畦のかど・畦と平行に寄った所では、前へは どう切っても動けない。なぞりの間だけ まっすぐ下がってから（`TRACE.backLeft`）浅く切って出る。確かめる場所：`x:-11.2, z:23.6, yaw:-1.69`。
  - `firstmin.js` は 25 個・5 分ほど。持ち主の場面（前へ なぞって止まる）・見える地面の横なぞり・畦のかど を足した。
- **短い なぞり**（サイクル264）：
  - 本物の指は 0.2〜0.5 秒で離す。指を離すと止まる（サイクル116）ので、動けるのは 指を置いている間だけ。前へ 0.3 秒で 1 回 0.5m。
  - 寄せた横なぞり（`TRACE.pull`）は、線に着く前から 指の側へ切る。置いた長さと向きの変わり方（スマホ縦・田んぼの中）：0.7 秒 14°・1.4 秒 40°・0.5 秒ですぐ離すのを 6 回で 90°。0.3 秒ですぐ離す なぞりは 今も ほとんど曲がらない（進む長さが 10cm ほどしかない）。
  - 確かめは `firstmin.js` の 6（本物のタッチ：Codex の 6→12→18→24→25px・外の視点からの横なぞり・お題ありの切り返し・短い なぞり）。ぜんぶで 37 個・10 分ほど。
- **止まった人への見本**（サイクル265。運営者の実機の声 2026-11-10「曲がるお手本が出ない」）：
  - 決まりは 1 つ：指を離して止まったまま 2 秒で、なぞり方の見本を出す（`HINT.update`）。前に耕す所が続いていれば「前へ」、なければ「横へ」（耕す所が多い側）。
  - 曲がり方を覚えるまで（30° 以上 曲がれた なぞりが 3 回＝`HINT.sideOK`）は、前に 6m ぶん続いていなければ「横へ」を先に出す。止まったまま 6 秒ごとに 2 つを入れかえる。
  - 指がふれた・動きだした・操作の表や終わりの画面が出た ら すぐ消す。最初の1分のあとは、覚えるまでだけ出す。畦で止められたときの見本（サイクル260）は別で、今までどおり。
  - 条件を細かく分けない（「まだ 40° 曲がっていない人だけ」「前に耕す所がない人だけ」と分けたら、少し曲がって 絵の角で止まった人に 何も出なかった）。
- **横なぞりは画面の上で見る**（サイクル266。運営者の実機の声 2026-11-10「曲がり方がわからない」のつづき）：
  - 寄せた横なぞり（`TRACE.pull`）の「指の横の位置」は、指の下の地面ではなく、画面のまん中から指までの横の角度で決める（11m 先の地面での長さに直す。拡大前の画角 `baseFov` で見る）。
  - 地面で見ていたときに起きたこと（スマホの本物のタッチ・0.4 秒なぞって 1.5 秒置く）：

  - **回した あとの 指**：向きが かわったら 線を 消すだけで なく、指の 記録も ほかの 窓へ 行った ときと 同じに 消す（`viewPtsClear`・`PRE.clear`）。置いたままの 指は 次に 動いたら その 場所から おぼえ直し、12px で また なぞれる（前の 線は つづけないので とばない）。指を 離させる 案より こちらに した（サイクル274 で ほかの 窓から もどった 指と 同じ 道・前の 線が とぶ 心配が ない）。120px 動かして 2 秒で 0.02m → 2.3m。
  - **読みこみの 見はり**：ゲームが 読みはじめたら（`window.game`）、数えるのは 線と ゲームの ファイル（`.glb`・`/draco/`）だけ。ほかの 通信が 5 秒ごとに 終わる ときも 車体が 止まれば 知らせ（32 秒 出ない → 11.7 秒）。three の 3 本を 読む間（20 秒）は サイクル275 の まま。
  - **耕す前に 顔を 押す 人**（設計の 見直しの 案 A。`SAY.tap`）：まだ 1 ますも 耕して いない 間の 最初の 1 回は、雑談の かわりに はじめの 案内と 同じ 文「田んぼを ゆびで なぞる」を 言う。2 回めから・耕しはじめた あとは 今までどおり 雑談。新しい 文は 作って いない。数：開いて 3 秒から 1 秒に 1 回 顔を 押す 人の 10 回のうち、する ことを 言う 回 0 → 1（のこり 9 回は 雑談の まま）。
  - 確かめは `firstmin.js` の 16（16-1 こまの 速さ 5 個・16-2 回した あと 1 個・16-3 ほかの 通信 1 個・16-4 顔を 押す 1 個）。ぜんぶで 163 個。
- **本物の 3D で見てわかったこと**（サイクル261。three r128 を `scripts/node_modules/three` に入れて見た）：
  - スマホ縦の運転席は、画面の下 55% がハンドル・ボンネット・足。まん中は 9m ほど先まで ボンネットに かくれる。指の見本や目印は、8m より先の高さに置く。

## 作るときに気をつけること（今夜までに出たまちがい）

- **色**：`renderer.outputEncoding = sRGB`。新しい色は `new THREE.Color(hex).convertSRGBToLinear()` にする（しないと白っぽく、うすくなる）。
- **InstancedMesh**：`frustumCulled = false` にする。r128 は形の範囲が原点のままなので、田んぼのまん中が画面の外だと、まるごと消える。
- **地面の高さ**：畦・農道の土手・田んぼで高さがちがう。株や花・チョウは 1 つずつ高さを求める（浮く・もぐる）。
  - 田んぼ 0（代かきは −0.07）、畦 0.3、農道 0.5。
  - `ground(x, z)`、坂は x>12・z 18〜22。
- **向き**：
  - 前は `(sin yaw, cos yaw)`、左は `(cos yaw, −sin yaw)`（トラクターの中の座標は 前＝+Z・左＝+X。`wheelPoints` の `w(lx, lz)` で lx が正なら左、負なら右）。右は その逆。
  - `S.x, S.z` は後車軸で、鼻先はその 3.05m 前。
  - ます目は `tilledMask[i*NZ+j]`（i は x、j は z、`CELL=0.2`）。
- **トラクターの中に入らない**：鳥や虫が逃げるとき・急降下するときの距離は、後車軸ではなく車体のまん中か鼻先から測る。高さは屋根（約 2.7m）より上にする。
- **止まっているあいだ**（メニュー・操作の表・おわり）は `step()` が回らない。毎こま動く物は、実際に動いた距離で出す（`S.v` だけ見ると、止まっていても出つづける）。
- **初期化の順番**：モジュールを作るときは、まだ `S` がない（`const S` はあと）。作るときに `S` を読まない。
- **Web Audio**：
  - 予約は `AudioParam`（`gain.gain` など）に。`GainNode` に予約すると毎回例外になり、鳴きつづける。
  - 作った音のノードは必ず `stop()` する。
  - `audio` は始めるボタンのあとで作られるので、それより前に鳴らす音は、鳴らせるようになってから鳴らす。
- **毎こまの処理**で配列やオブジェクトを作らない（使い回す）。
- **シェーダ**：`onBeforeCompile` で `project_vertex` を置きかえると、風のゆれを株の向きに関係なく同じ向きにできる。Lambert の光と霧はそのまま正しい。
- **季節・時間・天気の出しわけ**：
  - `season`、`TOD`、`DARK`（夕と夜）、`RAIN`、`SHIRO`（代かき）、`WX`。
  - 昼の生きものは `DARK || RAIN` で出さない。コメントとコミットの「昼」と合わせる。
- **数を有限に**：同じ所を耕しなおしても、生きもの（例：タニシ）が増えないようにする。
- **安全の助言は正確に**：
  - 回っている爪に手を出さない。
  - 上げた作業機の下は、油圧を止めて台でささえる。
  - PTO の変速は止まってから。
  - 巣は耕さずに残してよける。

## 別の目での見なおし

まとまった変更のあとは、サブエージェント（general-purpose）に「直さずに報告だけ」の見なおしを頼むと、Codex が見のがしたまちがいが見つかる（今夜は 2 回で 8 件）。

- 頼むときに渡すもの：diff の範囲・モジュールの説明・上の座標の決まり・テストの仕方。
- 返ってきた指摘は、再現スクリプトで確かめてから直す。
