らいすぴあ 品質判定AI ／ Marketing Studio

近藤米穀店「らいすぴあ」のための、ビルド不要の静的Webアプリです（Vercel：https://ricepia-judge.vercel.app/ で公開）。

## アプリ

| ファイル | 内容 |
|---|---|
| `index.html` | 精米品質AI判定（写真→12項目採点・グレード判定・レシート印刷） |
| `marketing.html` | **らいすぴあ Marketing Studio**（AIマーケティング統合ツール） |
| `tsunagu.html` | **本店⇔支店**。本店と支店をビデオ通話でつなぐだけのシンプルなページ。ID・パスワード不要で、開くだけで自動的につながる |
| `meeting.html` | **らいすぴあ ミーティング**（Zoomのようなビデオ会議）。発言を自動で文字起こしし、AIがお客様のニーズを抽出して開発バックログ・GitHub Issue・開発依頼書につなげる |
| `meta-ads.html` | Meta（Facebook / Instagram）広告の成果診断。広告マネージャのCSVを読み込み、CPA・ROAS・CTR・フリークエンシー・前後半の推移から「増額／維持／要改善／停止／データ不足」を判定し、AIが改善策と次の広告案を提案 |

## 本店⇔支店（`tsunagu.html`）

1. 本店の端末で `tsunagu.html` を開き「つなぐリンクを作る」→「LINEで支店に送る」→「本店としてつなぐ」。
2. 支店の端末で届いたリンクを開く。以降はどちらも開くだけ（ホーム画面に追加推奨）で自動的につながる。相手が開いていなければ待機し、開いた時点でつながる。

- リンクに推測できないランダムな文字列（16文字）が入り、その組み合わせの本店・支店どうし以外からの着信は受けない。リンクは店の外に出さないこと。
- 端末ごとに「本店／支店」とリンクの文字列を localStorage に記憶。同じ店の画面を2か所で開くと案内を表示。
- 通話はWebRTCで端末どうしが直接やりとり（接続の仲介はPeerJSの公開サーバー）。録音・文字起こしはしない。
- 予備のZoom：初回設定（または ⚙ 設定）でZoomのミーティングURL（pwd= 付き）を入れると、両店に「Zoom」ボタンが出る。押すとこの画面の通話を切ってからZoomを開く（カメラ・マイクの取り合いとハウリングを避けるため、同時には使わない）。つながらないまま30秒たつと待機画面にも案内を表示。本店で後から設定した場合は ⚙ から支店にリンクを送り直す。

## ミーティング（`meeting.html`）の機能

| 区分 | 機能 | 概要 |
|---|---|---|
| 会議 | ビデオ会議 | ブラウザだけで参加できるビデオ通話（目安6人まで）。招待リンクをLINE・メールで送信、ミュート・カメラ・画面共有・チャット・参加者一覧 |
| 会議 | 自動文字起こし | 参加者それぞれの端末が自分の発言をブラウザの音声認識で文字にし、話者名・参加区分（当社／お客様）つきで全員に共有。字幕表示、ミュート中は自動停止、開始・停止は全員に通知 |
| 会議 | 録音 | 「⏺ 録音」で全員の音声をミックスして録音し、押した人の端末（IndexedDB）に保存。録音中は全員の画面に表示 |
| 会議 | AIメモ | 会議の途中で「ここまでの要望」と「次に聞くとよいこと」をAIが整理（聞き漏らし防止）。手書きメモも記録に残る |
| 分析 | 要望分析 | 文字起こしから明示・潜在ニーズを抽出し、根拠の発言（時刻つき）、優先度（Must/Should/Could）、ユーザーストーリー、受け入れ条件、開発メモ、確認事項、次のアクションを整理。議事録（Markdown）とお客様への確認メール文面も作成 |
| 分析 | 取り込み | Zoom・Meet・Teams などの文字起こし（.vtt / .srt / .txt）と録音ファイルを取り込んで同じように分析 |
| 分析 | 聞き直し・修正 | 文字起こしの各発言と「お客様の声」の引用から録音をその位置で再生。誤変換の修正、話者の区分（お客様／当社）の切り替え。修正後は再分析を案内 |
| 開発 | 開発バックログ | 会議をまたいでニーズを蓄積。同じ目的の要望はAIが既存項目に統合し、言及数・優先度・影響からスコア順に並べる。状態管理（新規→検討中→開発中→リリース済み） |
| 開発 | お客様の声レポート | 分析済みの全会議を横断し、よく出る困りごと・お客様のタイプ別の違い・新しい機会・開発ロードマップ案・次のヒアリングの仮説をAIがまとめる |
| 開発 | リリースのお知らせ | 項目を「リリース済み」にすると、要望してくれたお客様ごとに「いただいたご要望に対応しました」という文面案を作成（コピー・LINE送信・連絡済み管理） |
| 開発 | GitHub Issue / 開発依頼書 | 項目からお客様の声・受け入れ条件つきのIssueを作成（GitHubの新規Issue画面を開く）。選んだ項目から開発依頼書（Claude Code へそのまま渡せる依頼文つき）をAIが作成 |

- 通話：WebRTC（参加者どうしのメッシュ接続）。接続の仲介に PeerJS（`peerjs@1.5.4`、既定は公開サーバー）。自社のPeerServerを使う場合は `meeting.html?peerhost=ホスト&peerport=443&peerpath=/` で開く（`peersecure=0` で http）。
- 文字起こし：Web Speech API（Chrome / Edge / Safari）。Chrome では音声がブラウザ提供元の認識サーバーに送られる。
- データ：会議記録・バックログはブラウザの localStorage（キー接頭辞 `rmt_`）、録音は IndexedDB（`rmt_audio`、バックアップ対象外）。AI分析を実行したときだけ文字起こしを Anthropic API に送信。APIキーは Marketing Studio と共通（`rpm_key`）。
- AI：要望分析・開発依頼書は `claude-opus-5-5`（effort high、分析は JSON Schema の構造化出力）、会議中のAIメモは `claude-sonnet-5-5`（effort low）。

## 使い方

1. `marketing.html`（https://ricepia-judge.vercel.app/marketing.html）を開き、右上の「🔑」から Anthropic APIキーを設定（[console.anthropic.com](https://console.anthropic.com/settings/keys)）。
2. まず「ブランド設定」で所在地・営業時間・価格などの【　】部分を埋めて保存。
3. 「売上と配信」で月次KPIを、ホームの「数値を更新」で各SNS・LINEの数字を入れると、ホームの診断が具体的になります。

## 技術メモ

- 構成：`marketing.html` + `mkt/`（`style.css`, `core.js`, `charts.js`, `data.js`, `studio.js`, `plan.js`, `insight.js`, `home.js`）。外部ライブラリなし。
- AI：Anthropic Messages API をブラウザから直接呼び出し（SSEストリーミング）。既定モデル `claude-opus-5-5`（設定で `claude-sonnet-5-5` に切替可）、`effort` 指定、拒否時の `fallbacks: "default"`、リサーチは `web_search_20260209`（`pause_turn` の継続にも対応）。
- データ：すべてブラウザの localStorage（キー接頭辞 `rpm_`）。APIキーは既定でセッション内のみ保持。
- 品質判定との連携：`index.html` が最新の判定結果を `ricepia_last_judge` に保存し、コンテンツ生成画面で利用。
- 注意：APIキーをブラウザで扱う構成のため、店内の信頼できる端末での利用を想定しています。複数店舗・多人数で運用する場合は、APIキーをサーバー側に置くバックエンド（認証付き）への移行を推奨します。
