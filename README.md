らいすぴあ 品質判定AI ／ Marketing Studio

近藤米穀店「らいすぴあ」のための、ビルド不要の静的Webアプリです（Vercel：https://ricepia-judge.vercel.app/ で公開）。

## アプリ

| ファイル | 内容 |
|---|---|
| `index.html` | 精米品質AI判定（写真→12項目採点・グレード判定・レシート印刷） |
| `marketing.html` | **らいすぴあ Marketing Studio**（AIマーケティング統合ツール） |
| `nishio-go.html` | **にしおさんぽGO**（西尾市のお散歩ポイントラリー）。地図上のスポット（神社・お寺・公園・史跡・駅など）に歩いて近づくとチェックインでき、ポイント・レベル・バッジが貯まる |
| `tsunagu.html` | **つなぐ**。店舗どうしをビデオ通話でつなぐだけのページ。開くだけで最大5台がひとつの部屋に入る（設定・ID・パスワード不要） |

## つなぐ（`tsunagu.html`）

店舗どうしをビデオ通話でつなぐだけのページ。設定・ID・パスワード・リンクの受け渡しは不要で、各端末で https://ricepia-judge.vercel.app/tsunagu.html を開くだけ（ホーム画面に追加推奨）。

- 右上の「↻ 再起動」：録音を保存し、席を空けてから最新版のページで開き直す（ホーム画面から開いたアプリには再読み込みボタンがないため）
- 開くと最初に「マイクをオンで入る／ミュートで入る」を選ぶ（「切る」のあと「つなぐ」で入り直すときも同じ）。ミュート中は上部に「🔇 ミュート中」を表示
- 相手の映像は1画面に1台ずつ大きく表示し、相手が2台以上のときは横スワイプ（または下の点をタップ）で切り替える。自分の映像は右下に小さく表示
- ひとつの部屋に最大5台。開いた順に席（1〜5）に入り、ほかの席に自動で発信する。6台目は「満室」と表示し、空くと自動で入る。台数が増えるほど1本あたりの映像の画質（ビットレート）を自動で下げ、5台でも端末と回線に負担をかけすぎないようにする
- 接続の仲介サーバーとの連絡が途切れても、端末どうしの映像・音声は切らずに続け、裏で仲介サーバーにつなぎ直す。通話が切れたら2〜4秒でかけ直す。iPad で回線が切り替わって「一時的に切断」のまま止まった接続は、8秒待ってからかけ直す。経路探しに Google・Cloudflare の STUN を追加
- 相手が閉じる・回線が切れる・タブレットがスリープから戻る、などでも自動で再接続。だれかが入ると音で知らせ、上部に「n台でつながっています」と表示
- 予備のZoom：「Zoom」ボタンで、この画面の通話を切ってから らいすぴあのZoom（パーソナルミーティングID 544 001 0563、`https://zoom.us/j/5440010563`）を開く。⚙ で pwd= 付きの招待リンクを入れるとパスコード入力が不要になる（その端末にだけ保存）。つながらないまま30秒たつと待機画面にも案内
- 注意：URLを知っていればだれでも入れるため、公開ページ（品質判定など）からはリンクしていない。URLは店の外に出さないこと
- 記録：ほかの端末とつながっている間は自動で録音・文字起こしし、画面右上に小さな赤ポチを表示。各端末が全員の声をまとめて録音し、自分の声を文字起こしして相手にも送るので、どの端末にも全員分の記録が残る（話者は「端末1〜5」）。ミュート中はその端末の文字起こしを止める。記録は1時間ごとに区切り、ミーティングの「履歴」（`つなぐ` の印）に保存され、そこから要望分析・録音の再生ができる（自動処理は動かさない）。録音は7日、文字起こしは60日で自動削除。ページを急に閉じても、録音はミーティングを開いたときに復元される
- 通話はWebRTCで端末どうしが直接やりとり（接続の仲介はPeerJSの公開サーバー）

## ミーティング（`meeting.html`）の機能

| 区分 | 機能 | 概要 |
|---|---|---|
| 会議 | ビデオ会議 | ブラウザだけで参加できるビデオ通話（目安6人まで）。招待リンクをLINE・メールで送信、ミュート・カメラ・画面共有・チャット・参加者一覧 |
| 会議 | 自動文字起こし | 参加者それぞれの端末が自分の発言をブラウザの音声認識で文字にし、話者名・参加区分（当社／お客様）つきで全員に共有。字幕表示、ミュート中は自動停止、開始・停止は全員に通知 |
| 会議 | 録音 | 「⏺ 録音」で全員の音声をミックスして録音し、押した人の端末（IndexedDB）に保存。録音中は全員の画面に表示 |
| 会議 | AIメモ | 会議の途中で「ここまでの要望」と「次に聞くとよいこと」をAIが整理（聞き漏らし防止）。手書きメモも記録に残る |
| 分析 | 要望分析 | 文字起こしから明示・潜在ニーズを抽出し、根拠の発言（時刻つき）、優先度（Must/Should/Could）、ユーザーストーリー、受け入れ条件、開発メモ、確認事項、次のアクションを整理。議事録（Markdown）とお客様への確認メール文面も作成 |
| 分析 | 取り込み | Zoom・Meet・Teams などの文字起こし（.vtt / .srt / .txt）と録音ファイルを取り込んで同じように分析 |
| 分析 | 聞き直し・修正 | 文字起こしの各発言と「お客様の声」の引用から録音をその位置で再生。誤変換の修正、話者の区分（お客様／当社）の切り替え。修正後は再分析を案内 |
| 開発 | 開発バックログ | 会議をまたいでニーズを蓄積。同じ目的の要望はAIが既存項目に統合し、言及数・優先度・影響からスコア順に並べる。状態管理（新規→検討中→開発中→リリース済み） |
| 開発 | お客様の声レポート | 分析済みの全会議を横断し、よく出る困りごと・お客様のタイプ別の違い・新しい機会・開発ロードマップ案・次のヒアリングの仮説をAIがまとめる |
| 開発 | リリースのお知らせ | 項目を「リリース済み」にすると、要望してくれたお客様ごとに「いただいたご要望に対応しました」という文面案を作成（コピー・LINE送信・連絡済み管理） |
| 開発 | ⚡ 自動化 | 会議が終わると自動で「要望分析 → 開発バックログ → GitHub Issue（Must など対象を選べる）→ Claude Code に開発を依頼（Issue に `claude-dev` ラベル）」まで進める。設定は「開発バックログ」の「⚡ 自動化」。GitHub は Issues の読み書きだけを許可した fine-grained トークンを使い、その端末にだけ保存（バックアップには含めない）。公開リポジトリには、お客様の名前と発言の引用を載せない。同じ要望が別の会議で出たら既存の Issue にコメント。途中で失敗しても「⚡ 自動処理を実行」で続きから再開 |
| 開発 | Claude Code による開発 | `.github/workflows/claude-dev.yml`：Issue に `claude-dev` ラベルが付くと Claude Code（`anthropics/claude-code-action@v1`）が受け入れ条件に沿って実装し、ブランチと結果を Issue に報告。コメントで `@claude` と書くと追加の指示に答える。取り込み（マージ）は人が確認して行う。リポジトリに Actions シークレット `ANTHROPIC_API_KEY` と Claude GitHub App が必要 |
| 開発 | GitHub Issue / 開発依頼書 | 項目からお客様の声・受け入れ条件つきのIssueを作成（GitHubの新規Issue画面を開く）。選んだ項目から開発依頼書（Claude Code へそのまま渡せる依頼文つき）をAIが作成 |

- 通話：WebRTC（参加者どうしのメッシュ接続）。接続の仲介に PeerJS（`peerjs@1.5.4`、既定は公開サーバー）。自社のPeerServerを使う場合は `meeting.html?peerhost=ホスト&peerport=443&peerpath=/` で開く（`peersecure=0` で http）。
- 文字起こし：Web Speech API（Chrome / Edge / Safari）。Chrome では音声がブラウザ提供元の認識サーバーに送られる。
- データ：会議記録・バックログはブラウザの localStorage（キー接頭辞 `rmt_`）、録音は IndexedDB（`rmt_audio`、バックアップ対象外）。AI分析を実行したときだけ文字起こしを Anthropic API に送信。APIキーは Marketing Studio と共通（`rpm_key`）。
- AI：要望分析・開発依頼書は `claude-opus-5-5`（effort high、分析は JSON Schema の構造化出力）、会議中のAIメモは `claude-sonnet-5-5`（effort low）。

## 使い方

1. `marketing.html`（https://ricepia-judge.vercel.app/marketing.html）を開き、右上の「🔑」から Anthropic APIキーを設定（[console.anthropic.com](https://console.anthropic.com/settings/keys)）。
2. まず「ブランド設定」で所在地・営業時間・価格などの【　】部分を埋めて保存。
3. 「売上と配信」で月次KPIを、ホームの「数値を更新」で各SNS・LINEの数字を入れると、ホームの診断が具体的になります。

## 技術メモ

- 構成：`marketing.html` + `mkt/`（`style.css`, `core.js`, `charts.js`, `data.js`, `studio.js`, `plan.js`, `insight.js`, `home.js`）。外部ライブラリなし。
- AI：Anthropic Messages API をブラウザから直接呼び出し（SSEストリーミング）。既定モデル `claude-opus-5-5`（設定で `claude-sonnet-5-5` に切替可）、`effort` 指定、拒否時の `fallbacks: "default"`、リサーチは `web_search_20260209`（`pause_turn` の継続にも対応）。
- データ：すべてブラウザの localStorage（キー接頭辞 `rpm_`）。APIキーは既定でセッション内のみ保持。
- 品質判定との連携：`index.html` が最新の判定結果を `ricepia_last_judge` に保存し、コンテンツ生成画面で利用。
- 注意：APIキーをブラウザで扱う構成のため、店内の信頼できる端末での利用を想定しています。複数店舗・多人数で運用する場合は、APIキーをサーバー側に置くバックエンド（認証付き）への移行を推奨します。

## にしおさんぽGO（`nishio-go.html`）

ポケモンGOのポケストップのように、西尾市内のスポットへ実際に歩いて行くとポイントが貯まるゲームです。

- **遊べる範囲**：西尾市と、となりの市町（岡崎市・安城市・碧南市・高浜市・幸田町・蒲郡市）、それに近藤米穀店（本店）から半径15km（刈谷・知立・半田・東浦・阿久比・武豊など。`game.js` の `CFG.home`）。市町の境界は `nishio-go/region.js`（`tools/bake-region.js`・`.github/workflows/bake-region.yml` が国土数値情報「行政区域データ」（N03・愛知県）から作り、約60mに間引いたもの。取れないときは OpenStreetMap の行政界から。OpenStreetMap の西尾市と安城市の境は米津町のあたりが粗く、本店が安城市に入ってしまうため）。歩く地図の区画はこの境界から約300m以内か、本店から15km（＋約300m）の円にかかるものだけ作り、せかいちずには市町の境を白い点線で描きます。となりの市町にも、注目スポット69か所（岡崎20・安城13・碧南15・高浜8・幸田10・蒲郡3）、話しかけられる人26人、毎年の行事28件、名物10件（八丁味噌・額田のお米「たべりん」・日本デンマークの農業・安城の梨・碧南のにんじん・本みりん・三州瓦と鬼瓦・筆柿など）を入れ、西尾の人と となりまちの人がおたがいを紹介します（お米・田んぼの話でつながる）。各項目の出典は `src`。バッジは「○○制覇」が市町ごと、「となりまちの名物めぐり」「となりまちの顔なじみ」は西尾と別。

- 地図：国土地理院の地理院タイル（淡色地図）＋ Leaflet 1.9.4（unpkg、SRI付き）。
- スポット：OpenStreetMap（Overpass API）から **西尾市の行政区域内** の神社・お寺・史跡・公園・博物館・展望所・図書館・駅・海岸を自動取得（端末に7日間キャッシュ）。取得できないときは注目スポットだけで動きます。
- 注目スポット：`nishio-go/spots.json` に84か所（西尾34・一色6・佐久島9・吉良21・幡豆14。当店2か所を含む）。すべて座標つき（Wikipedia・マピオン・NAVITIME、2026年10月に西尾市観光協会のスポット紹介と「西尾の秋まつり」から足した22か所は、紹介ページの住所を国土地理院の住所検索で座標にしたもの。OpenStreetMap・Wikidata でも確かめた）。`match` の名前で OSM の同じ名前の場所を探し、確かな座標なら300m、概算（`approx: true`）なら1km以内で見つかればその位置に補正します。`normal: true` はふつうのスポット（OpenStreetMap にない社寺を Wikidata から足したもの）。
- ふつうのスポット（`nishio-go/osm-spots.json`）：神社・お寺・公園・史跡・博物館・展望地・駅・海岸・庭園・山頂・滝・支所などを、GitHub Actions（`.github/workflows/bake-spots.yml`・`tools/bake-spots.js`）が OpenStreetMap から作り、毎週作り直します（問い合わせはゲームと共通の `nishio-go/osm-query.js`）。ゲームはまずこのファイルを使うので、Overpass が混んでいても全部のスポットが出ます。
- 西尾の人たち（`nishio-go/npcs.js`）：注目スポットのそばに30人。実在の人ではなく、その場所にいそうな人（茶畑のおじいさん、魚屋のおかみさん、観光ボランティアガイドなど）。話す中身は地区ガイド・スポットの説明・行事・ricepia.jp に書いてある事実だけで、ことばは三河弁を少し。ドット絵の地図ではぶつかるかタップ、ふつうの地図では絵文字をタップで話しかけます（操作して移動は30m、あるいて移動は60m以内）。はじめて話すと +10pt、その場所の今月・来月の行事も教えてくれます。
- ポイント：スポット10pt（注目30〜50pt）、初訪問 +30pt（注目 +100pt）、その日最初のチェックイン +20pt＋連続日数ボーナス、100m歩くごとに1pt（1日100ptまで。ページを開いて画面がついている間だけ数える）。同じスポットは60分ごと。数値は `nishio-go/game.js` 冒頭の `CFG` で調整できます。
- 不正対策（簡易）：チェックインは約40m以内＋GPS誤差の上乗せ（最大25m）、GPS精度80m超は不可、時速約30km超の移動を検知すると2分間は歩いた距離を数えない（乗り物＝電車・バス・同乗の車での移動中も、チェックイン・たからばこ・行き先に着くことはでき、運転している人は操作しないよう知らせる）、更新が3分以上途切れた間の移動は歩数に数えない。

- 車（操作して移動・ドット絵の地図）：スティックのとなりの🚗で、白い軽トラに乗り降りします。道（灰色の道路）の上かとなりで乗れて、道だけを倍の速さで走れます（人がいると止まる）。乗っている間は歩いたポイント・チェックイン・たからばこ・話しかけはお休みで、降りるとできます。地図のタップなどで道の外へ移動したときは自動で降ります。
- せかいちず（ドット絵の地図の🌏ボタン）：西尾市と となりの市町（岡崎・安城・碧南・高浜・幸田・蒲郡）、本店から15km（西は半田・武豊まで）を1マス100mのドラクエ風フィールドマップで表示。はじめて開く人は、このダンジョン風のせかいちずから始まります。海・丘・山は国土地理院の標高タイル（ズーム12）から、川・国道・県道・線路・森・町なみと地名・駅名は OpenStreetMap から作り、注目スポット（名所57か所すべて）と大きな建物をドット絵で重ねます（寄ると名所の名前も表示。中くらいの縮尺から川の名前（水色）、いちばん寄ると町名（灰色の小さな文字）も出します。めぐった名所には金色の✓が付き、左上に「めぐった名所 n/全体」を表示。駅が名所になっている所は駅名を重ねて出さない）。地図データは「地名・駅・大きな建物」1回と、範囲を4×4に分けた16回（自分に近い区域から順）に分けて取り込み、取れた区域から順に道や川が描き足されます（左上に「ちずを くわしくしています… n/16」）。1回で全域を取ると無料サーバーで時間切れになりやすいためです。引いて見ると1マス＝色のブロックの全体図、寄るとドット絵タイル。いちばん寄ってさらに拡大すると歩く地図に、歩く地図をいちばん引いてさらに縮小するとせかいちずに切り替わります。ドラッグで移動、アイコンをタップで説明。作った地図は端末に30日保存（取れなかった区域があれば1日で作り直し）（この縮尺では海岸線を使わず、標高データのない所を海とみなし、地図データで森や町なみがある所は陸にします）。
- せかいちずの地図データ（`nishio-go/world.json`）：GitHub Actions（`.github/workflows/bake-world.yml`）が、ゲームと同じ `pixel.js` をヘッドレスのブラウザで動かして、実際の OpenStreetMap と国土地理院の標高タイルから作ります。このときは川・道・線路・森・町なみに加えて、田んぼ・茶畑・畑・工場・境内・墓地・公園・学校・砂浜・干潟・養鰻池なども、範囲を8×8に分けて取り込みます（歩く地図と同じ分け方）。ゲームはまずこのファイルを読むので、開いてすぐ西尾市全体の地図が出ます（端末に7日保存）。ファイルがない・大きさが合わないときだけ、ブラウザで軽い地図データを取って作ります。作り直すときは、Actions の「Bake Nishio world map」を手動で実行するか、`tools/world-version.txt` の数字を上げてプッシュします（せかいちずの作り方を変えたときも）。
- **家と建物は本物の場所に（版3から）**：区画を作るとき、`tools/gsi-buildings.js` が国土地理院のベクトルタイル（`experimental_bvmap` の建物。基盤地図情報 1/2500 の建物の形）から、西尾の建物を1軒ずつ置きます。250㎡までの建物は、その中心のマスに家の絵（Blender の家）、大きい建物は形どおりに屋根を塗ります（30㎡より小さい物置と、小さな屋根だけの小屋は描きません）。屋根の色は、国土地理院の空中写真（全国最新写真（シームレス）、ズーム17）で建物の内側を49点見た色の中央値から、瓦（灰・黒・茶・青・赤茶）・金属（青・赤・緑・銀・黄土）・陸屋根（白・明るい灰）のいちばん近いものを選び、区画データの `r` に入れます（家は白い屋根なら陸屋根の家、ほかは同じ色の屋根の家）。建物用地で建物のない所は町の地面、家のまわりは庭（草と植木）です。国土地理院の建物がある区画では、OpenStreetMap の建物と「建物用地に家を並べる」作り方は使いません。出典は区画の README と、地図の右下の「地理院タイル」。
- 歩く地図の区画データ（`nishio-go/chunks/区画.json`）：GitHub Actions（`.github/workflows/bake-chunks.yml`）が `tools/bake-chunks.js` で、遊べる範囲（西尾市と となりの市町、本店から15km）にかかる1km四方の区画をすべて、実際の OpenStreetMap（2×2区画ずつまとめて取得）と国土地理院の標高から、ゲームと同じ `rasterize()` で作ります（ランレングスで保存）。ゲームはまずこのファイルを読み、なければブラウザで地図データを取ります。ふだんは まだない区画と、作ったときの版（ファイルの `cv`）が `tools/chunks-version.txt` より古い区画だけを作るので、作り直すときは数字を上げてプッシュします（1回の実行は4時間まで。残りがあれば、作った分をコミットしたあと自動でもう一度起動します。`nishio-go/region.js` が変わったときも、区画を作り直します）。
- 地区ガイド（`nishio-go/areas.json`）：西尾市を西尾・一色・吉良・幡豆・佐久島の5地区に分け、特徴・名物・人口・面積・豆知識を出典付きでまとめたもの（2026年10月調査）。せかいちずに地区の札（めぐった名所の数）を出し、タップで地区ガイドを表示。`spots.json` の各注目スポットの `area` で地区を決め、きろくの「地区ごとのめぐり具合」と「○○制覇」バッジに使います。

## バックアップ（restic）

このリポジトリ（すべての履歴と、まだコミットしていない変更）を [restic](https://restic.net/) で暗号化してバックアップする。スクリプトは `tools/restic-backup.sh`。保存先はクラウドと外付けSSDの2か所にする（GitHub とあわせて3か所。3-2-1ルール）。

- **クラウド（毎日自動）**：`.github/workflows/restic-backup.yml` が毎日 3:17 に動く。GitHub のシークレットに `RESTIC_REPOSITORY`（例 `s3:https://<アカウントID>.r2.cloudflarestorage.com/<バケット>`）と `RESTIC_PASSWORD`、保存先の鍵（R2・S3 は `RESTIC_AWS_ACCESS_KEY_ID`・`RESTIC_AWS_SECRET_ACCESS_KEY`、B2 は `B2_ACCOUNT_ID`・`B2_ACCOUNT_KEY`）を入れる。入れるまでは何もしない
- **外付けSSD（自分のパソコンで）**：Mac の例
  ```sh
  brew install restic
  security add-generic-password -s restic-ricepia -a "$USER" -w    # パスワードをキーチェーンに保存（聞かれたら入力）
  export RESTIC_REPOSITORY=/Volumes/<SSDの名前>/restic-ricepia
  export RESTIC_PASSWORD_COMMAND="security find-generic-password -s restic-ricepia -w"
  bash tools/restic-backup.sh       # はじめての時は保存先も作る。2回目からは変わったところだけ
  ```
- **元に戻す**：`restic snapshots` で一覧、`restic restore latest --target ./restore` で取り出す（`.git` ごと戻るので、履歴もそのまま）
- パスワードをなくすと元に戻せない。パスワード管理アプリにも控えておく。チャットやファイルには書かない
- 残す数：毎日7・毎週4・毎月12（古いものは自動で消す）
