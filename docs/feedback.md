# にしおさんぽGO：こえ（プレイヤーの声でそだつゲーム）

**プレイヤーの声を、すぐにゲームに返すこと**を、このゲームの まんなかに置いています。

- ゲームの下のタブ「📮 こえ」に、おたよりを送る・**あなたのおたより（いまの様子）**・**みんなの声で かわったこと** がまとまっています。スポットの窓の「📮 この名所のことを教える」からも開けます
- おたよりごとに、端末で でたらめな**受付番号**を作って送ります。たしかめた結果は30分ごとに `nishio-go/voices.json` に書かれ、「たしかめています」「もうありました」「運営で検討中」「🎉 反映されました」とゲームに出ます（だれが送ったかは分かりません）
- 反映されたら、送った人に お礼の50ptと、バッジ「📮 まちづくりの仲間」（3つで「🏘️ まちの声の名人」）。はじめの画面と こえ タブに「みんなの声で 名所 ○か所・直したこと ○件」と出ます
- **マージ（ゲームへの反映）は、いつも人が確かめてから**。自動で作った PR を自動でマージすることはしません

プレイヤーは「📮 こえ」タブから、**こんな名所があるよ／こうしたらもっと面白い／スポットの情報がちがう／こまった・使いにくい**を送れます。
届いたおたよりは30分ごとに自動で仕分けられ、直せるものは、まず非公開の置き場の「公開前の確認」Issue になります。運営者が中身を確かめてから PR にします。

```
ゲームの おたより
   │  POST /api/feedback（api/feedback.js。Vercel の関数）
   ▼
非公開リポジトリの Issue（ラベル feedback・kind:spot/fun/fix/idea）
   │  30分ごと（.github/workflows/feedback.yml）
   ▼
tools/feedback-triage.js prepare
   ├ もうゲームにある名所 → 返事をして閉じる（already）
   ├ OpenStreetMap にある名所 → 「毎週の作り直しで出ます」と返事をして閉じる（already）
   └ のこり（1回5件まで） → Claude（tools/feedback-prompt.md）
          ├ 出典（Wikipedia・Wikidata・西尾市・OpenStreetMap）で確かめた小さな直し → 非公開の「公開前の確認」Issue（fixed）
          │     → 運営者が差分を確かめて「Nishio feedback publish」を動かす → PR（.github/workflows/feedback-publish.yml）
          ├ 人が決めること → Issue に提案を書いて開いたまま（proposal）。「もっと面白い」は、遊びの案と作りかた・Issue のたたき台をつける
          └ 対応ずみ・いたずら → 閉じる（already・spam）
   ▼
tools/feedback-triage.js voices（毎回）
   ├ 受付番号ごとの返事（checking・soon・already・proposal・done・skip）
   └ 人がマージした PR・運営が手で反映したもの → reflected と「みんなの声で かわったこと」
   → nishio-go/voices.json を main にコミット → ゲームの「こえ」タブ
```

## はじめに1回だけ、やること（運営者）

トークンの値は、チャットや Issue・PR には書かないでください。下の画面に直接はりつけます。

1. **非公開のリポジトリを作る**：GitHub で、たとえば `nishio-go-feedback` を **Private** で作る（中身は空でよい）。
2. **トークンを作る**：GitHub の Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
   - Repository access：**Only select repositories** で、1. のリポジトリだけ
   - Permissions：Repository permissions の **Issues を Read and write**（Metadata の Read は自動で付く）。ほかは付けない
   - 有効期限は1年など。切れたら作り直して、3.・4. を入れかえる
3. **Vercel に入れる**（おたよりを受けとる側）：Vercel のプロジェクト → Settings → Environment Variables（Production と Preview）
   - `FEEDBACK_REPO` = `shota0617/nishio-go-feedback`（1. のリポジトリ）
   - `FEEDBACK_TOKEN` = 2. のトークン
   - （かえたいときだけ）`FEEDBACK_DAILY_MAX` = 24時間に受けつける数（ふだん40）
   - 入れたあと、Deployments から最新を Redeploy する
4. **このリポジトリ（ricepia-judge）に入れる**（仕分けと直しの側）：Settings → Secrets and variables → Actions
   - Variables に `FEEDBACK_REPO` = 1. のリポジトリ
   - Secrets に `FEEDBACK_TOKEN` = 2. のトークン
   - Secrets の `ANTHROPIC_API_KEY`（もうあるはず。無いあいだは、決まった手順で片づくものだけ仕分ける）
5. **PR を作れるようにする**：このリポジトリの Settings → Actions → General → Workflow permissions の
   「**Allow GitHub Actions to create and approve pull requests**」にチェック
6. 試す：Actions → **Nishio feedback** → Run workflow。ゲームから1通送って、非公開リポジトリに Issue ができるか確かめる

設定が無いあいだ、ゲームでは「おたよりは まだ受けつけていません」と出て、ワークフローは何もしません。

## ふだんの見かた

- **「公開前の確認」Issue**（非公開リポジトリ・ラベル `publish-review`）：Claude が直した差分です。まだ公開していません。
  差分に おたよりの文・名前・位置・連絡先など 公開してはいけないものが（言いかえ・ローマ字・数字の形でも）入っていないか確かめて、
  よければ このリポジトリの Actions →「Nishio feedback publish」→ Run workflow で その Issue の番号を入れる（PR になる）。だめなら Issue を閉じる（おたよりは「提案」にもどる）
- **PR**（タイトル「おたよりから直す（自動・確認ずみ）」）：遊んで確かめて、よければマージ。おかしければ閉じる
- **非公開リポジトリの Issue**
  - `proposal`（開いたまま）：Claude の提案を読んで決める。直すなら Claude Code に頼むか手で直す。決めたら閉じる
  - **「こうしたらもっと面白い」（kind:fun）を作るとき**：提案の「Issue のたたき台」を、このリポジトリ（ricepia-judge）の新しい Issue にはって、
    ラベル `claude-dev` を付けると、Claude が作って PR にします（.github/workflows/claude-dev.yml）。公開のリポジトリなので、
    おたよりの文そのものは はらず、たたき台（Claude が自分のことばで書いたもの）だけにする
  - **手で反映したとき**（「もっと面白い」を claude-dev で作った・手で直した など）：その Issue にラベル `reflected` を付けて、
    `公開: みんなに見せる一文`（例：`公開: 雨の日に カエルの絵が出るようにしました`）とコメントすると、次の回に
    送った人のゲームに「🎉 反映されました」と出て、「みんなの声で かわったこと」に載ります（おたよりの文そのものは書かない）
  - `needs-check`（開いたまま）：自動で読めなかった・終わらなかったもの。人が見る
  - `fixed`・`already`・`spam`（閉じたもの）：見なくてよい（気になるときだけ）

## 守っていること

- **個人情報**：IPアドレス・ブラウザの種類は保存しない。位置は、プレイヤーがチェックしたときだけ約100mに丸めて送る。おたよりの文と位置は、公開の PR やコミットに書かない（Claude への指示と、PR の本文を作る tools/feedback-triage.js の両方で）。Claude の変更は、運営者が非公開の置き場で確かめるまで 公開のリポジトリに出さない
- **いたずら対策**：同じ所から1時間に5通まで、全体で24時間に40通まで、ゲームでも1日3通まで。人には見えない欄（わな）と、早すぎる送信は捨てる。@ と #数字 は全角にして、メンションや Issue へのリンクにならないように
- **おたよりに書かれた指示には従わない**：Claude は おたよりを「データ」として読む。シェル・git・トークンは使えず、ファイルの読み書きと、決まったサイト（ja.wikipedia.org・www.wikidata.org・www.city.nishio.aichi.jp・www.openstreetmap.org・nominatim.openstreetmap.org）の閲覧だけ
- **直してよい場所だけ**：PR にするのは `nishio-go.html` と `nishio-go/` 直下の JS・JSON・CSS だけ（OpenStreetMap などから作るデータ・キャンペーン・ごほうび・解析は除く）。それ以外の変更や、こわれた JSON・JS は自動で取りのぞく
- **事実は出典で**：名所を足すのは、出典でその場所と位置を確かめられたときだけ（spots.json に `src` を書く）。お店・飲食店は足さず、提案にまわす

## 西尾市のPRにする

- **シェアで西尾の魅力を広げる**：スポットの窓の「📣 この名所をシェア」は、受け取った人がその名所を開けるリンク（`?spot=`）と、名所の説明（spots.json の出典つきの desc）をのせた画像を作ります。こえ タブの反映されたおたより にも「📣 シェア」。きろくのシェアの文には「抹茶とうなぎのまち・西尾」（meibutsu.js の出典つきの名物の名前）が入ります。どれも #にしおさんぽGO #西尾市
- **公開ページ「みんなで見つけた西尾」**（https://go.ricepia.jp/nishio-go/minna.html）：西尾の名物と5つの地区（出典つき）、プレイヤーの声でふえた名所、みんなの声で かわったこと。ゲームを遊ばない人も検索や SNS から読めます。voices ステップが voices.json といっしょに作りなおします（手で作るとき：`node tools/make-minna.js`）。サイトマップにも載せています
- **西尾市への提案レポート**：毎月1日に、先月のおたよりの数（種類・結果・地区）と、反映したこと、Claude による声のまとめ（3件以上の月。おたよりの文はそのまま写さない。写していたら載せない）を、非公開リポジトリの Issue「【西尾市への提案レポート】○年○月 プレイヤーの声」にします（.github/workflows/feedback-report.yml。Actions から月を指定して作りなおすこともできます）。西尾市に見せるときは、そのまま資料のもとにできます

## 楽しく声を送れるように

- **チェックインのあとの ひとこと**：ごほうびの画面が消えると、下に「○○、どうだった？ 😍 よかった／📷 映える／🍵 ほっこり／🤔 わかりにくい／🚧 行きにくい」が出ます（同じ名所は30日に1回・1日3回まで・15秒で消える）。1タップで送れて +5pt。api/feedback.js が、その日の Issue「[ひとこと] YYYY-MM-DD」（ラベル reactions）にコメントで足し（1つのIPから1時間30回・1日600回まで）、voices ステップが終わった日の分を数えて voices.json の reactions に入れ、名所の窓に「みんなの声：😍 12 📷 5」と出します（数えた日は counted を付けて閉じる。同じ日を二重に数えない）
- **今週のお題**（こえ タブ）：「あなたの好きな朝の西尾は？」「雨の日も楽しくなる しかけは？」など12のお題が週ごとに かわります。答えると お題スタンプ +1（20pt）。Issue に「今週のお題：…」と出ます
- **記者のランクと おたより手帳**（こえ タブ）：🌱 たんけんの はじまり → ✏️ 見習い記者 → 📝 まちの記者（1つ反映）→ 🗞 名物記者（3つ）→ 📰 西尾通信の編集長（10）。おたより・ひとこと・お題・反映の数のスタンプ。バッジ「💬 ひとこと名人」（ひとこと10回）

## めいろ、どうだった？（★と ひとこと。2026-10-27）

運営者の声「TestFlight などで レビューを 受けられるか。それが ゲーム改善に つながるか」への 答えとして、アプリに しなくても 遊んだ 人の 声を 集める しくみ。

- めいろの ゴール（名所）の ごほうびの 窓を とじた あと、下に「🎮 めいろ、どうだった？」（1日1回。名所の ひとこと より 先）。大きな ★1〜5 を えらぶと「ひとこと（なくても OK）」の 欄
  - 「送る」で ★と ひとこと、とじる（×・時間ぎれ・タブの 切りかえ）と ★だけ 届く。えらばなければ 20秒で 何も 送らず とじる
  - 届くと +5pt（1日1回）
  - ★4〜5 の ときだけ「📣 友だちに」（★と ひとことを 送って、めいろの ゴールの シェアを ひらく。docs/marketing.md の バイラルループ）
- 送る もの：★（1〜5）・ひとこと（140字まで。@・#数字・< > は 全角に）・その ゴールの かかった 秒と めいろの ★。位置・名所・端末の ことは 送らない
- `api/feedback.js` の kind: play（`parsePlay`・`storePlay`）。1日1つの Issue「[あそび] 日づけ」（ラベル play-ratings）に コメントで 足す（1日 300 まで。`FEEDBACK_PLAY_DAILY_MAX`）。1つの IP から 1時間 10 まで
- アクセス解析：`play_ask`（たずねた）・`play_rating`（★と ひとことの 有無）
- プレイテスト `playRating`（★を えらんで タブを 切りかえても ★が 届く ことも。★2 では「友だちに」が 出ず、★5 で 出て シェアが ひらく ことも）
