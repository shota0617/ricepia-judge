## 2回目に直したこと（はじめは見送ったもの）

運営者のことば：「見送った指摘も直して」

| 指摘 | 直し方 |
|---|---|
| GitHub Actions の外の部品を、版の名前（`@v4`・`@v1`）で使っていた（あとから中身を差しかえられうる） | そのときの ぜんぶのワークフローで、版の コミットの SHA に固定（`actions/checkout`・`setup-node`・`upload-artifact`・`cache` の v4、`anthropics/claude-code-action` の v1。行の終わりに `# v4` などと残した）。版を上げるときは SHA も書きかえる |
| 社内ツール（`meeting.html`・`marketing.html`）の API キー・GitHub トークンを「記憶する」と ブラウザ（localStorage）に のこり、同じサイトの ほかのページに 穴があると ぬすまれうる | キーと トークンは このタブの あいだだけ（sessionStorage）に。「記憶する」を なくし、前に記憶した キー・トークンは 開いたときに 消す。タブを閉じたら もう一度 入れる。**これで のこる時間は短くなるが、同じタブで動く 同じサイトのスクリプトからは まだ読める**（会議の記録・録音も ブラウザに のこる）。守りきるには 社内ツールを べつのサイトに分ける（下の「まだ のこること」） |
| AI の遊びテスト（`play-improve.yml`）の Claude が どのファイルでも 書けた（遊ぶ道具 `tools/ai-play.js` を 書きかえて 動かせた） | 書けるのは `nishio-go/`・`nishio-go.html`・`docs/play-improve.md` だけに（3回目で `tools/playtest.js` も外した）。PR にするのも その場所だけで、ほかが かわっていたら PR に しない |
| ricepia.jp の FTP の やりとりを くわしく（`debug 3`）公開の ログに 出していた | `debug 1`（接続の結果と エラーだけ）に |
| 外から読む部品（CDN）に 改ざんチェックが なかった（トラクターの three.js・店内ビデオ通話と ミーティングの PeerJS） | `integrity`（sha384）と `crossorigin` を つけた。値は npm の 同じ版の ファイルから 計算した（three.js は npm と 同じ中身を 配る jsDelivr に 読み先を そろえた）。版を上げるときは 値も 計算しなおす |

| 指摘 | 直し方 |

| 高：AI に許した「文法の確かめ」から、AI が書いたスクリプトを 秘密のある所で動かせた（`play-improve.yml`・X サイクル）。play-improve では AI が書きかえた `tools/playtest.js` も そのあと動いた | node を じかに動かす許可をやめ、決まった確かめ（`node tools/x-cycle.js check …`。ファイルを読んで文法を見るだけ）だけに。play-improve の AI は `tools/playtest.js` を書けない（足したいチェックは `docs/play-improve.md` に書く）。AI が動かせるのは、AI が書きかえられない道具だけ。PR を作る git はフックを動かさない |

| 中：おたよりの API の 1日の上限が、同時に たくさん送られると 守られなかった | ひとつのインスタンスの中では 1件ずつ順に置く。置いたあとに もう一度数え、上限をこえていたら その Issue を閉じる（3つのインスタンスから同時に60件送る試験で、ちょうど40件） |
| 中：社内ツールのキーの守り・履歴の パスワードについて、この文書の書き方が 言いすぎだった | 上の表と はじめの文を なおした |
| 低：CSP が なかった | ぜんぶのページに 害のない最小の CSP（`object-src 'none'`・`base-uri 'self'`・`frame-ancestors 'self'`）。社内ツール（`meeting.html`・`marketing.html`・`meta-ads.html`・`tsunagu.html`）には、読みこみ先・通信先を しぼった CSP（キーを送れるのは Anthropic・GitHub・PeerJS だけ）。ゲームと 精米判定は、広告の計測を こわさないように 最小のまま |
| 低：AI が作るブランチ（`feedback/`・`x-cycle/`）が Vercel のプレビューに出うる | `vercel.json` で 出さないようにした |

## まだ のこること

- 社内ツールを べつのサイト（べつの Vercel のプロジェクト・サブドメイン）に分ける（運営者の 設定が いる。キーは もう ブラウザに のこらないので、急ぎでは ない）
- 社内ツールが べつのサイトになるまでは、同じタブで動く 同じサイトのスクリプトから キーが読める。CSP で 送り先は しぼったが、ほかのページに 穴を作らないことが いちばんの守り
- ゲーム・精米判定の CSP を しぼる（広告・計測のタグの 読みこみ先を ぜんぶ確かめてから）
- おたよりの API の上限を かんぜんに守るには、共有の置き場（Vercel KV など）で数える（いまは 置いたあとに閉じる）
- ricepia.jp（さくら）の ページの 外から読む部品（tailwind・chart.js など）：ricepia.jp への アップロードが いるので、運営者の OK が出たら
