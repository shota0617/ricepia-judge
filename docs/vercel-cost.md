# Vercel の費用をおさえる（2026年10月）

go.ricepia.jp は Vercel の Pro（月20ドル）で公開している。請求が ふくらまないように、次のようにしている。

## 1. Vercel の管理画面の設定（運営者が行う）

- **Spend Management（使いすぎの上限）**：Settings → Billing → Spend Management
  - 月20ドルの枠を こえた分（従量課金）の上限を決める（例：5〜10ドル）
  - 50%・75%・100% で メール・SMS の知らせ
  - 「Pause production deployments」をオンにすると、上限で サイトを止める（ほんとうの上限になる。止まっている間は 503 が出るので、ダッシュボードから再開する）
  - 判定は数分おきなので、少しだけ こえることがある。上限は低めに
- **Flat Rate CDN（CDN の定額）**：Pro では 月100万リクエストまで 定額にふくまれる
  - こえた月の次の月から、上の段（月 +20ドル・+100ドル・+300ドル）に上がる。上がる前に 7日以上前に知らせがある。1日だけの急な増え方では上がらない
  - 知らせが来たら、その前に 段を下げる・Flat Rate CDN をオフにする（従量の 100万リクエスト 2ドルになり、Spend Management の上限の中に入る）ことができる

## 2. ゲームのほうでの くふう（リクエストを へらす）

- 1回遊ぶと 約140リクエスト（はじめの画面だけで 約106）。いままでは 2回めからも 毎回すべてを 取りなおしていた（Vercel の ふつうの設定は「毎回 新しいか確かめる」で、確かめるだけでも 1リクエスト）
- `vercel.json` の `headers` で、ブラウザに しばらく とっておいてもらう：
  - 絵・地図のタイル・区画・音（`art` `maptiles` `deco` `bgm` `shots` `dots3d` `chunks`）と 大きなデータ（`landuse.json` `landmarks.json` `world.json`）：1日（そのあと7日は、古いものを使いながら うしろで 新しくする）
  - プログラム（`nishio-go/*.js` など）：5分（新しいプログラムと 古いプログラムが まざらないように 短く）
  - ページ（`nishio-go.html`）と、よく変わるデータ（`spots.json`・キャンペーンなど）：いつも新しく
- これで 同じ日に2回め以降は 約140 → 約45リクエストになる見こみ
- 気をつけること：絵を直して公開しても、もう遊んだ人には 最大1日ほど 古い絵が出ることがある
- まだ足りなくなったら：プログラムを1つにまとめる・絵を1枚のシートにまとめる・サービスワーカーで とっておく、で さらに へらせる

## 3. おたよりの関数（`api/feedback.js`）

- `vercel.json` の `functions` で、1回に動ける時間を 10秒までにした（GitHub への送信は 8秒で あきらめるので、ふだんは それより短い）。止まったままの呼び出しで 時間の料金が のびないように
- 受けつける数は、関数の中で 24時間に40まで・同じ人から1時間に5まで（docs/feedback.md）

## 4. アカウントが止まったとき（2026-10-23 にあったこと）

- 2026-10-23 の 13:51（日本時間）から、Vercel の公開が「Account is blocked.」で止まった（13:23 の公開が さいごの成功）。GitHub の PR・main の Vercel のチェックが すべて失敗になり、その間に main へ入った変更（西尾めいろ を より精巧に・#221）も 公開されなかった
- 運営者が Vercel の管理画面で 戻したあとも、止まっていた間の コミットは 自動では 公開しなおされない。戻ったら、次の どちらかで 公開する：
  - Vercel の Deployments で いちばん新しい main の行を開き、「…」→ **Redeploy**
  - main に 次の変更を 入れる（そのときに それまでの変更も いっしょに 公開される）
- 止まった わけは Vercel からの メールと、管理画面の アカウントの状態・請求・Spend Management で 確かめる
