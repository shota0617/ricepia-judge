# リモレジ — ビデオ通話しながら、画面越しにレジ会計

Zoom のようなビデオ通話と、Airレジのようなレジを 1 つにしたアプリです。お客様と顔を見ながら相談し、店員が商品をレジに登録すると、その明細がお客様の画面にそのまま表示されます。お客様は自分のスマホやパソコンで支払います。

**お支払いはクレジットカード（Airペイ）と PayPay の 2 種類だけです。**

## できること

| | 店員 | お客様 |
|---|---|---|
| つなぐ | 招待リンク・QRコード・6桁の入室コードを発行／お客様の「呼び出し」に応答（呼び出し音つき） | 入口ページの「店員を呼び出す」、または招待リンク・入室コードで入室 |
| 通話 | ビデオ・音声、マイク／カメラのオンオフ、**画面共有**（商品写真・カタログを見せる） | ビデオ・音声。**カメラはオフのままでも参加可** |
| レジ | 商品ボタンでカートに追加、数量変更、自由入力、値引き（マイナス金額） | 明細と合計がリアルタイムに表示される |
| 会計 | 「お会計」で支払いを依頼。支払い状況（方法を選択中／カード支払い中／PayPay 支払い中）が見える。取り消しも可 | クレジットカード（Airペイ）か PayPay を選んで支払う |
| 会計後 | 会計完了の表示、レシート番号、領収書 | 領収書（印刷・PDF 保存可）を表示 |
| 管理 | 商品の登録・編集・削除、日別売上（カード／PayPay／税率別）、CSV ダウンロード、**返金** | — |

### お支払いの仕組み

- **クレジットカード**：[Airペイのオンライン決済](https://airregi.jp/payment/service/online/)（決済リンク）を使います。Airペイには外部システムから使える API が公開されていないため、次の流れになります。
  1. お客様が「クレジットカード」を選ぶと、店員の画面に作業手順が出ます。
  2. 店員が Airペイの管理画面（オンライン決済 → 決済リンク管理）で、**都度決済・金額入り**の決済リンクを作り、URL をレジ画面に貼り付けて「お客様に送る」を押します。
  3. お客様の画面に「Airペイで支払う」ボタンと QR が出ます。お客様は Airペイの画面でカード情報を入力して支払い、「支払いが終わりました」を押します。
  4. 店員が Airペイの管理画面で入金を確認し、「入金を確認した → 会計完了」を押します（Airペイの取引番号を控えておけます）。お客様の申告だけでは会計済みになりません。
  - カード情報は Airペイが直接受け取るため、お店や店員には見えません。対応ブランドは Visa / Mastercard / JCB / American Express / Diners Club、決済手数料は Airペイのオンライン決済の料率（3.24%）です。
  - 金額をお客様が入力するタイプのリンクを使う場合は、`.env` の `AIRPAY_LINK_URL` に入れておくと、毎回の貼り付けを省略できます（その場合、お客様が正しい金額を入力したか必ず確認してください）。
- **PayPay**：[PayPay for Developers](https://developer.paypay.ne.jp/) のウェブペイメントで、その場で金額入りの支払いQRを作ります。スマホのお客様は「PayPayアプリで支払う」ボタンでアプリが開き、パソコンのお客様は表示された QR をスマホの PayPay で読み取ります。支払い完了は自動で検知され、両方の画面が「会計完了」に切り替わります。
- 金額は必ずサーバー側のカートから計算します。お客様の画面から送られた金額は使いません。PayPay の支払い完了は PayPay の API に問い合わせて確認してから記録します。
- 途中で支払い方法を変えたり会計を取り消したりすると、PayPay の QR を取り消します。取り消しの直前に支払いが済んでいた場合は、二重請求にならないよう会計済みとして扱います。Airペイのリンクを送った後に取り消すときは、お客様がすでに支払っていないか Airペイの管理画面で確認するよう店員画面に表示します。
- 返金：PayPay は「返金」ボタンで PayPay API から返金します。カード（Airペイ）は API がないため、Airペイの管理画面で取引を取り消してから「返金」ボタンで記録します。

### 税・レシート

- 価格はすべて税込（内税）。商品ごとに税率 10% / 8%（軽減税率）を設定します。
- 消費税は**税率ごとに合計してから 1 回だけ端数（切り捨て）処理**します（インボイス制度のルールどおり）。
- 領収書には店名・住所・電話番号・**登録番号（T + 13 桁）**・税率ごとの対象額と消費税額・軽減税率対象の印（※）を載せます。

## まず動かしてみる（デモモード）

Node.js 22.13 以上が必要です。

```sh
cd remoreji
npm install
npm start
```

- 店員：<http://localhost:3000/staff>（デモモードはパスワードなしでログイン）
- お客様：<http://localhost:3000/>（別のブラウザやシークレットウィンドウで開く）

PayPay の鍵が未設定の間は**デモモード**です。PayPay は擬似 QR（スマホで読み取るとデモの支払い画面が開きます）、カードは店員画面の「デモ用リンクを送る」で擬似的な Airペイ画面を試せます。実際のお金は動きません。

> カメラ・マイクは `localhost` か `https://` のページでしか使えません。スマホで試すときは https で公開してください（下記）。

## 本番で使うまで

1. **サーバーを用意して https で公開**します。Docker の場合：
   ```sh
   docker build -t remoreji .
   docker run -d -p 3000:3000 -v remoreji-data:/data --env-file .env remoreji
   ```
   前段に https 終端（Caddy / nginx / Cloudflare など）を置いてください。WebSocket（`/ws`）も通るように設定します。nginx などの後ろに置く場合は `TRUST_PROXY=1` を設定します。
2. `.env.example` を `.env` にコピーして、`BASE_URL`・`STAFF_PASSWORD`・お店の情報を記入します。
3. **Airペイ**（カード）：Airペイの利用を開始していれば、オンライン決済は追加の手続きなしで使えます。決済リンクの作成は PC または iPad の管理画面から行います（スマホでは作れません）。
4. **PayPay**：PayPay for Developers で加盟店登録をして、API キー・シークレット・加盟店 ID を設定します。最初は `PAYPAY_ENV=sandbox`（テスト環境）で試し、審査が通ったら `production` にします。Webhook（任意）は `https://<BASE_URL>/webhooks/paypay` を登録します（届かなくても数秒ごとの確認で支払い完了を検知します）。
5. **TURN サーバー**：お客様のスマホ（携帯回線）とお店のネットワークの組み合わせによっては、STUN だけでは映像が繋がりません。Cloudflare Calls の TURN、Twilio、自前の coturn などを `TURN_URLS` / `TURN_USERNAME` / `TURN_CREDENTIAL` に設定してください。
6. 店頭の QR コードやお店のサイト・SNS に入口ページ（`BASE_URL` のトップ）を載せると、お客様が「店員を呼び出す」から呼び出せます。

## 画面とURL

| URL | 内容 |
|---|---|
| `/` | お客様の入口（店員を呼び出す／入室コード） |
| `/r/<トークン>` | お客様の通話・支払い画面（招待リンク） |
| `/staff` | 店員ダッシュボード（呼び出し一覧・招待・商品・売上） |
| `/staff/room/<ID>` | 店員のレジ画面（通話＋商品登録＋会計） |
| `/receipt/<トークン>` | 領収書 |

## セキュリティ・プライバシー

- 通話はブラウザ同士の直接通信（WebRTC・暗号化）で、サーバーには映像・音声を保存しません（録画・録音しません）。
- カード情報はお店のサーバーを通りません（Airペイが直接受け取ります）。お客様に渡すのは店員が貼り付けた https のリンクだけで、画面には支払い先のドメインも表示します。
- 招待リンクは推測できないランダムな文字列です。入室コードは接客中だけ有効で、総当たりはレート制限で防ぎます。接客を終了するとリンクもコードも使えなくなります。
- 店員画面は署名付き Cookie でログインを確認し、別サイトからの操作（CSRF・WebSocket 乗っ取り）は Origin を確認して拒否します。
- お客様は明細を見て支払うだけで、カートは操作できません。

## 開発

```sh
npm test   # 税計算・署名・会計の流れ（Airペイ／PayPay デモ）・PayPay 連携（モック）のテスト
npm run dev
```

| ファイル | 役割 |
|---|---|
| `src/server.js` | HTTP（画面・API・領収書・Webhook） |
| `src/hub.js` | WebSocket（通話の接続情報の中継、レジ画面のリアルタイム配信） |
| `src/rooms.js` | 接客ルームとカート |
| `src/payments.js` | 会計・決済（Airペイの決済リンク／PayPay）・返金・売上集計 |
| `src/paypay.js` | PayPay API の最小クライアント（SDK 不要） |
| `public/call.js` | ブラウザ側のビデオ通話（WebRTC） |
| `public/register.js` / `public/customer.js` / `public/staff.js` | 店員のレジ画面／お客様画面／ダッシュボード |

1 プロセスで動かす前提です（接続状態とレート制限はメモリ上に持ちます）。データは `DATA_DIR`（既定 `data/`）の SQLite に保存されます。
