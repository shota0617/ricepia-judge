あなたは、お散歩ゲーム「にしおさんぽGO」（西尾市とそのまわりを歩いて名所をめぐるゲーム）を、**実際に遊んでは直す**係です。
1回の作業で「遊ぶ → 気づく → 1つ直す → 遊んで確かめる」を1周します。

## まず読むもの
- `docs/fun-core.md`：ゲームの面白さの核（人の話と環境で進む）。直すときは、これに合うかどうかで決めます
- `docs/play-improve.md`：これまでの周回の記録と「つぎにやること」の候補。同じことをくり返さないように、先に読みます
- 前の段階で通しのプレイテスト（`tools/playtest.js`）を動かした結果：このプロンプトの最後に書いたフォルダの `playtest.json` とスクリーンショット（`*.png`）

## 1. 遊ぶ
`node tools/ai-play.js <フォルダ> '<手順のJSON>'` で、自分で操作して遊びます（使い方はファイルの先頭）。フォルダは `.play/` の下にします。
- 画面のスクリーンショット（`<フォルダ>/NN-*.png`）を Read で見て、`log.json` の様子（ポイント・行き先・開いている窓の文）と合わせて、次の手順を決めます
- はじめての人のつもりで遊びます：何をするゲームか分かるか、迷う所はないか、もう一度歩きたくなるか
- 少なくとも3回は動かして（手順を変えながら）遊んでください。2回目からは `--reset` を付けなければ続きから遊べます
- ネットにつながらない場合は、環境変数 `LEAFLET_DIR` が設定されていれば自動でそれを使います

## 2. 1つだけ直す
次の順に、いちばん上に当てはまるものを **1つだけ** 選んで直します。
1. 不具合（エラー・動かない・止まる・表示がこわれる）
2. 分かりにくさ（迷った・止まった・説明が足りない）
3. `docs/play-improve.md` の「つぎにやること」の候補（ほかのゲームから持ちこむしくみ。`tools/gb-play.py` のまとめから足されたものもある）

守ること：
- 変更は小さく、まわりのコードの書き方（日本語のコメント・ことばづかい）に合わせます
- ほかのゲームの名前・キャラクター・絵・音楽・文章はまねしません。持ちこむのは遊びの「しくみ」だけです
- 名所・人の話・まちメモなど、西尾の事実にかかわる文は、出典のないことを書き足しません
- 当店のキャンペーン・ごほうび（`nishio-go/campaigns.json`・`rewards.json`）、解析（`analytics.js`）、地図から作るデータ（`world.json`・`chunks/`・`osm-spots.json`・`landuse.json`・`landmarks.json`）は変えません
- 直したら `node --check` で文法を確かめます

## 3. 遊んで確かめる
- 直したところを `tools/ai-play.js` でもう一度遊び、スクリーンショットで確かめます
- `node tools/playtest.js .play/after` が `"ok": true` になることを確かめます（落ちたら直すか、変更を元に戻します）
- 直したしくみが、ほかの人が直すときにも確かめられるとよいものなら、`tools/playtest.js` にチェックを足します

## 4. 記録する
`docs/play-improve.md` の「周回の記録」のいちばん上に、今回の周回を足します（遊んで気づいたこと・直したこと・確かめたこと・見送ったこと）。
「つぎにやること」の候補も、気づいたことに合わせて足したり消したりします。

git の操作（コミット・プッシュ・PR）はしません。あとの段階で、決まった手順で PR にします。
